# 実装のレビュー（開発の流れ 3/4）

対象: $ARGUMENTS

## 手順

1. `ps-reviewer` エージェントにレビューを依頼する
   - 渡すのは、対象のフォルダ（`tools/<名前>/`）とツール名だけ。実装の経緯や、自分の判断の理由は伝えない（先入観を持たせないため）
2. 返ってきた指摘を 1 件ずつ確かめる
   - 再現できるものは `powershell.exe`（5.1）で試す
   - 誤りだと判断した指摘は、理由を添えて「直さない」に分ける
3. 正しい指摘を直す
   - README（仕様）を変える必要がある指摘で、使い方や出力が大きく変わるものは、直す前にユーザーに相談する
   - 直したら、回帰テストがあれば `tests/Invoke-Tests.ps1 -Name <名前>` を実行する
4. 重大度が「重大」または「中」の指摘を直した場合は、もう一度 `ps-reviewer` に確認してもらう（最大 2 回まで）
5. レビューで見つかった問題は、テストフェーズで再発防止のテストにするため、一覧に残しておく

## 終わり方

- 指摘と対応の一覧（直した／直さない＋理由）を、ユーザーに報告する
- 重大な指摘で相談が必要なものがなければ、そのまま `/tool-test` に進む
