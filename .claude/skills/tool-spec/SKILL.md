# 要件（開発の流れ 1/4）

対象: $ARGUMENTS

## 手順

1. `CLAUDE.md` を読み、開発の流れとルールを確認する
2. 企画書（`doc/SE支援ツール公開 企画書.md` のツール候補一覧）と、既存のツール（`tools/`）を確認する。似た処理があれば、出力の形や書き方をそろえる
3. どんな場面で使う道具かを 1〜2 文で決める
4. たたき台を作ってユーザーに見せる
   - 画面の表示例（実際の見た目に近い形で）
   - パラメーターと既定値
   - 保存するファイルと、CSV の列（見出しは日本語）
   - 集計や判定のルール、異常時の扱い（権限エラー、リンク、長いパスなど）
   - 対象外の環境と、使うときの注意
5. ユーザーが決めるべき点（ツール名、既定の動き、最初の版に入れる機能など）は、`AskUserQuestion` でまとめて聞く。おすすめがあれば先頭に置く
6. 決まった内容で `tools/<名前>/README.md` を書く。構成は `tools/Get-DiskUsage/README.md` に合わせる。読み手はツールを使う SE・運用担当
7. 自分の判断で決めたところを、理由と一緒に一覧にして報告する

## 終わり方

- **ユーザーの OK をもらって止まる**。OK が出るまで `.ps1` を書かない
- OK が出たら、`/tool-dev` で開発に進むことを伝える
