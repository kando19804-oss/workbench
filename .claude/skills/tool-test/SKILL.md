# テスト（開発の流れ 4/4）

対象: $ARGUMENTS

## 手順

1. `tests/<名前>.Tests.ps1` を作る（すでにあれば足す）。構成は `tests/Get-DiskUsage.Tests.ps1` に合わせる
   - `Assert-Equal`、`Write-Skip`、`Write-Section` で結果を出し、終了コードは失敗の件数にする
   - ダミー環境は一時フォルダに作り、終了時に削除する。アクセス拒否などの設定は、必ず元に戻してから削除する
   - 入れるテスト
     - 正常系: README の使い方の例と、パラメーターの組み合わせ
     - 異常系: 権限なし、日本語やスペースを含むパス、260 文字を超えるパス、リンクのループ、存在しないパス、書き込めない保存先
     - 起動: `-File` での引数、コマンドプロンプトからの起動、終了コード
     - レビューで見つかった問題の再発防止
     - 実機にしかない条件（Windows の互換用リンクなど）は、存在するときだけ試し、ないときは `Write-Skip` にする
2. `powershell -ExecutionPolicy Bypass -File .\tests\Invoke-Tests.ps1 -Name <名前>` を実行し、5.1 と 7 の両方で全部合格するまで直す
3. テストがバグを見つけられるかを確かめる。大事な処理にわざとバグを入れて、テストが失敗することを確認し、**必ず元に戻して**からもう一度全部合格することを確かめる
4. 実際に使う規模で一度動かす（例: `C:\` 全体。読み取りのみ）。結果に不自然な点（同じ値の行が並ぶ、合計が多すぎるなど）がないかを見る
5. ユーザーに、実機（管理者の Windows PowerShell 5.1）で試すコマンド一式と、見てほしい項目のチェックリストを渡す

## 終わり方

- **ユーザーの実機確認の結果をもらうまで止まる**。問題があれば直して、2 からやり直す
- OK が出たら、ルートの `README.md` のツール一覧を更新し、目的ごとに分けてコミットして push する
