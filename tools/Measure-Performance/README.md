# Measure-Performance（性能の記録）

このコンピューターの CPU・メモリ・ディスク・ネットワークの使われ方と、CPU やメモリを多く使っているプロセスを、一定の間隔で記録します。止めると、期間中の平均と最大、目安を超えた時間帯、重かったプロセスをまとめて表示し、記録と一緒に CSV に保存します。

「サーバーが遅いと言われたが、何が重いのか分からない」というときや、夜間バッチ・バックアップ・負荷試験の間の様子を残しておきたいときのための道具です。パフォーマンス モニターのようにカウンターを選んだり、データ コレクター セットを作ったりする必要はありません。Windows の表示の言語によらず、同じ見出し・同じ単位（MB、ms、Mbps）の CSV になります。設定を変更したり、プロセスを止めたりすることはありません。

## 使い方

```powershell
# Ctrl+C で止めるまで、5 秒ごとに記録する
powershell -ExecutionPolicy Bypass -File .\Measure-Performance.ps1
```

管理者でなくても使えます。実行ポリシーなど、起動方法の詳しい説明は[リポジトリの README](../../README.md#使い方) を参照してください。

### 例

```powershell
# 30 分だけ記録する
powershell -ExecutionPolicy Bypass -File .\Measure-Performance.ps1 -Duration 30

# 夜間バッチの間、30 秒ごとに 8 時間記録する
powershell -ExecutionPolicy Bypass -File .\Measure-Performance.ps1 -Interval 30 -Duration 480

# 特定のプロセスは、上位に入らなくても毎回記録する（メモリが増え続けていないかを見る）
powershell -ExecutionPolicy Bypass -File .\Measure-Performance.ps1 -Process "w3wp,java"

# IIS の接続数も一緒に記録する（カウンターは英語の名前で書けます）
powershell -ExecutionPolicy Bypass -File .\Measure-Performance.ps1 -Counter "\Web Service(_Total)\Current Connections"

# 保存せず、画面で見るだけにする
powershell -ExecutionPolicy Bypass -File .\Measure-Performance.ps1 -NoSave

# 設定ファイルに書いた条件で記録する
powershell -ExecutionPolicy Bypass -File .\Measure-Performance.ps1 -ConfigFile .\nightly.ini
```

## パラメーター

| パラメーター | 内容 | 既定値 |
| --- | --- | --- |
| `-Interval` | 記録する間隔（秒）。1～3600 で指定します | 5 |
| `-Duration` | 記録する時間（分）。1～10080（7 日）で指定します。時間がたつと自動で止まります。Ctrl+C で途中で止めることもできます | 指定なし（Ctrl+C で止めるまで） |
| `-Top` | 毎回記録するプロセスの数。CPU を多く使っている上位と、メモリを多く使っている上位を、それぞれこの件数まで記録します。0～50 で指定します。0 にすると、プロセスを毎回は記録しません（`-Process` で指定したものは記録します。終わったときのまとめと `process-list.csv` も作ります） | 5 |
| `-Process` | 上位に入らなくても毎回記録するプロセスの名前。`w3wp` か `w3wp.exe` のように書きます。`*` を使えます（`sql*`）。`*` 以外の文字（`[` `]` など）は、そのままの文字として扱います。大文字と小文字は区別しません。複数指定するときは、`"w3wp,java"` のようにカンマで区切って 1 つの文字列にします | 指定なし |
| `-Counter` | 一緒に記録するカウンター（[追加のカウンター](#追加のカウンター)を参照）。`\Web Service(_Total)\Current Connections` のように英語の名前で書きます。複数指定するときは、カンマで区切って 1 つの文字列にします（かっこの中のカンマは区切りにしません） | 指定なし |
| `-OutputFolder` | 記録の保存先 | スクリプトと同じフォルダ |
| `-NoSave` | 記録を保存せず、画面表示だけにします。`-OutputFolder` と一緒には使えません | なし |
| `-ConfigFile` | 設定ファイルのパス（[設定ファイル](#設定ファイル)を参照）。コマンドラインで指定した値は、設定ファイルより優先します | 指定なし |

## 記録する値

### CPU とメモリ（system.csv）

| 列 | 内容 | 元のカウンター |
| --- | --- | --- |
| CPU 使用率(%) | すべての論理プロセッサの平均の使用率です | `\Processor Information(_Total)\% Processor Time` |
| 最も忙しいコア(%) | 論理プロセッサごとの使用率のうち、最も高いものです。全体の使用率が低くても、1 つのコアだけで動く処理が CPU を使い切っていないかが分かります | `\Processor Information(*)\% Processor Time` |
| プロセッサ待ち行列 | CPU が空くのを待っているスレッドの数です | `\System\Processor Queue Length` |
| メモリ使用率(%) | （物理メモリの全体 − 空きメモリ）÷ 物理メモリの全体です。タスク マネージャーの「メモリ」と同じ考え方です | `\Memory\Available Bytes` |
| 空きメモリ(MB) | すぐに使えるメモリ（スタンバイと空き）です | `\Memory\Available Bytes` |
| コミット(MB) | プログラムが確保したメモリの合計です（ページ ファイルに置かれている分を含みます） | `\Memory\Committed Bytes` |
| コミットの上限(MB) | 確保できるメモリの上限です（物理メモリとページ ファイルの合計） | `\Memory\Commit Limit` |
| コミット率(%) | コミット ÷ コミットの上限です。上限に達すると、プログラムがメモリを確保できずに失敗します | `\Memory\% Committed Bytes In Use` |
| ページ読み込み(回/秒) | メモリの内容をディスクから読み込んだ回数です。メモリが足りずにページ ファイルから読み戻すと増えます（ファイルを開くときにも増えるため、これだけでメモリ不足とは決められません） | `\Memory\Page Reads/sec` |
| プロセス数 | 動いているプロセスの数です | `\System\Processes` |

### ディスク（disks.csv）

ドライブ（論理ディスク）ごとに 1 行を記録します。ドライブ文字のないボリューム（フォルダにマウントしたものなど）は、`HarddiskVolume5` のような名前になります。

| 列 | 内容 | 元のカウンター |
| --- | --- | --- |
| 使用時間(%) | 100 − アイドルの時間の割合です | `% Idle Time` |
| 応答時間(ms) | 読み書き 1 回にかかった平均の時間です | `Avg. Disk sec/Transfer` |
| 読み取りの応答時間(ms)、書き込みの応答時間(ms) | 読み取りと書き込みに分けた応答時間です | `Avg. Disk sec/Read`、`Avg. Disk sec/Write` |
| 回数(回/秒) | 読み書きの回数（IOPS）です | `Disk Transfers/sec` |
| 読み取り(MB/秒)、書き込み(MB/秒) | 読み書きした量です | `Disk Read Bytes/sec`、`Disk Write Bytes/sec` |
| 待ち行列 | 記録した瞬間に、処理中か順番を待っている読み書きの数です | `Current Disk Queue Length` |
| 空き(GB)、空き(%) | ドライブの空き容量です | `Free Megabytes`、`% Free Space` |

カウンターはすべて `\LogicalDisk(*)\` のものです。

### ネットワーク（network.csv）

ネットワーク アダプターごとに 1 行を記録します。

| 列 | 内容 | 元のカウンター |
| --- | --- | --- |
| アダプター | ネットワーク接続の名前（「イーサネット」など）です。接続の名前が分からないアダプターは、説明と同じにします | |
| 説明 | アダプターの説明（`Intel[R] Ethernet Connection I219-LM` など。カウンターの名前の決まりで、`(` `)` は `[` `]` に、`#` `/` は `_` に変わります） | |
| 受信(Mbps)、送信(Mbps) | 受信と送信の速さです（メガビット毎秒） | `Bytes Received/sec`、`Bytes Sent/sec` |
| 使用率(%) | 受信と送信の大きいほう ÷ 速度です（受信と送信は同時に速度いっぱいまで使えるため、合計では割りません） | |
| 速度(Mbps) | アダプターのつながっている速度です | `Current Bandwidth` |

カウンターはすべて `\Network Interface(*)\` のものです。Hyper-V の仮想スイッチの vEthernet や、VPN の仮想のアダプターは、このカウンターに出ないことがあり、そのときは記録しません（物理のアダプターを通る通信は、物理のアダプターで記録します。内部の仮想スイッチの中だけの通信は記録されません）。

### プロセス（processes.csv、process-list.csv）

プロセスの値は、性能カウンターではなく、Windows が持っているプロセスの一覧から読みます。値はパフォーマンス モニターの `\Process(*)\` のカウンターと同じものです。カウンターは `svchost#3` のような名前で区別するため、途中でプロセスが終わると番号がずれて、別のプロセスの値と混ざることがあります。一覧から読むと、PID と起動した時刻でプロセスを見分けられます。管理者でなくても、すべてのプロセスの値を読めます。

| 列 | 内容 | パフォーマンス モニターのカウンター |
| --- | --- | --- |
| プロセス | タスク マネージャーの「詳細」と同じ名前です（`sqlservr.exe`、`System` など） | |
| CPU(%) | PC 全体（すべての論理プロセッサ）を 100% とした使用率です。タスク マネージャーの「詳細」の CPU と同じ考え方です | `% Processor Time` ÷ 論理プロセッサの数 |
| メモリ(MB) | プライベート ワーキング セットです（タスク マネージャーの「詳細」の「メモリ」） | `Working Set - Private` |
| コミット(MB) | そのプロセスが確保したメモリです（タスク マネージャーの「コミット サイズ」）。増え続けるときは、メモリリークを疑います | `Private Bytes` |
| I/O(MB/秒) | ファイル・ネットワーク・デバイスの読み書きの合計です | `IO Data Bytes/sec` |
| ハンドル数、スレッド数 | 増え続けるときは、ハンドルやスレッドのリークを疑います | `Handle Count`、`Thread Count` |
| サービス | そのプロセスで動いている Windows のサービスの名前です。複数あるときは `, ` で区切ります | |

- 同じ名前のプロセスが複数あっても（`svchost.exe` など）、PID で見分けます
- 毎回、CPU(%) の上位と、メモリ(MB) の上位を、それぞれ `-Top` の件数まで `processes.csv` に記録します。`-Process` で指定したプロセスは、上位に入らなくても記録します
- 前の回の後に起動したプロセスは、起動してから使った分を、その回の値にします
- 終わったときのまとめと `process-list.csv` は、記録しなかったプロセスも含めた、すべてのプロセスから計算します
- アイドル（System Idle Process）と、このツール自身は、順位と記録から外します。このツールの CPU 使用率は、終わったときに表示します

### 記録の仕方

- 使用率・回数・転送量などは、前の回からの間の平均です。待ち行列・空き・コミット・ハンドル数などは、記録した瞬間の値です。間隔より短い一瞬の負荷は、平均されて小さく見えます。短い負荷を見たいときは、`-Interval` を短くしてください
- 最初の記録は、始めてから 1 間隔の後です（平均を出すには、2 回読み取る必要があるため）
- 記録の時刻は、始めた時刻から間隔ごとの予定の時刻にそろえます。予定の時刻は秒の区切りに合わせ、CSV には秒に四捨五入した時刻を書きます（`-Interval 1` でも、同じ時刻の行が並ばないようにするためです）。1 回の記録に間隔より長くかかったとき（PC が非常に重いときなど）は、間に合わなかった回を飛ばして、次の予定の時刻から続けます
- 前の回から、間隔の 2 倍を超えて間があいたとき（スリープから戻ったときなど）は、その回は記録せずに、次の回から続けます（あいだの長い時間の平均になるため）
- 飛ばした回と記録しなかった回の数は、終わったときに表示します
- 記録の途中で増えたドライブ・アダプター・プロセスも、その回から記録します。なくなったものは、その回から記録しません
- 間隔より短い時間で終わったプロセスは、記録に残らないことがあります

## 画面の表示例

### 記録している間

```
性能の記録 (Measure-Performance 1.0.0)
対象: SERVER01（管理者: はい）  Windows Server 2022 Standard   2026-11-24 14:05:12
CPU: Intel(R) Xeon(R) Silver 4210R CPU @ 2.40GHz（論理プロセッサ 20）   メモリ 64.0 GB
ディスク: C:, D:   ネットワーク: Ethernet0（1 Gbps）
記録: 5 秒ごと・1 時間（15:05:12 まで）   プロセス: CPU とメモリの上位 5 件
保存先: C:\tools\Performance_SERVER01_20261124_140512
止めるときは Ctrl+C を押してください。それまでの記録を保存します。

 時刻        CPU     最大のコア  メモリ     ディスク（最も忙しい）    ネットワーク     CPU の 1 位
 14:05:17    12%            45%     63%     C:      8%    1.2 ms          1.6 Mbps     sqlservr.exe 8.1%
 14:05:22    93% *         100%     64%     D:     92%   38.5 ms *       98.1 Mbps     robocopy.exe 61.2%
 14:05:27    88%           100%     64%     D:     95%   41.2 ms *      102.4 Mbps     robocopy.exe 58.7%
```

- 1 回記録するごとに、1 行を表示します
- 「ディスク（最も忙しい）」は、ドライブと、その使用時間・応答時間です。応答時間が目安を超えたドライブがあれば、そのうち最も遅いもの、なければ使用時間が最も高いものを表示します
- 「ネットワーク」は、すべてのアダプターの受信と送信の合計です
- 「CPU の 1 位」は、その回に CPU を最も使ったプロセスと、その使用率です。名前は半角 20 文字分で切り、最後を `...` にします
- [目安](#目安)を超えた値には `*` を付け、その行を黄色で表示します（`※` や `…` は、Windows ターミナルと Windows PowerShell のウィンドウで幅が変わり、列がずれるため使いません）。CPU は CPU 使用率かプロセッサ待ち行列、メモリはメモリ使用率かコミット率、ディスクは応答時間、ネットワークはどれかのアダプターの使用率が目安を超えたときに付けます（ディスクの空きは、終わったときのまとめにだけ出します）
- `-Duration` を指定しないときは、「記録」の行が「記録: 5 秒ごと・Ctrl+C で止めるまで」になります。60 分より短いときは「30 分間」、60 分以上は「8 時間」「1 時間 30 分」のように表示します
- `-ConfigFile` を指定したときは、「対象」の次の行に「設定ファイル: C:\tools\nightly.ini」を表示します
- `-Process` を指定したときは、「プロセス」が「CPU とメモリの上位 5 件、指定 w3wp, java」になります。`-Top 0` で `-Process` もないときは「毎回は記録しない」です
- `-Counter` を指定したときは、「記録」の次の行に「追加のカウンター: \Web Service(_Total)\Current Connections」を表示します（4 つ以上は「ほか 2 個」のように省きます）
- ディスクやネットワークのカウンターを読めないときは、「ディスク」「ネットワーク」を「記録しない」にし、次の行に理由を表示します。ドライブ・アダプターがないときは「なし」です
- `-NoSave` のときは「保存先」の行を表示せず、「止めるときは…」の行が「それまでのまとめを表示します。」になります。入力をリダイレクトして起動したときは「止めるときは…」の行を表示しません
- 「対象」の行の時刻と、保存先のフォルダ名の時刻は、記録を始めた時刻です（準備が終わってから、次の秒の区切りで取ります）。記録の時刻は、ここから間隔ごとに数えます

- 1 行目は、どう終わったか（「Ctrl+C」か「指定の時間」）と、記録した期間・回数です。期間の始めは、記録を始めた時刻（「対象」の行の時刻で、最初の記録の 1 間隔前）です。終わりは、Ctrl+C で止めた時刻か、指定の時間の終わり（「記録」の行の「（～まで）」の時刻）です
- 「最大」には、最大になった時刻を添えます（同じ値が複数あれば、最初の時刻）。記録を始めた日と違う日の時刻は、「11-25 02:10:05」のように月日も付けます
- ディスクの「空き」は、最後に記録したときの値です
- ディスクの応答時間の平均は、読み書きのあった回だけで出します（読み書きのない回の 0 で、平均が小さく見えないようにするためです）
- ディスクはすべてのドライブを表示します。ネットワークは、期間中に通信のあったアダプターだけを表示します（CSV にはすべて記録します）
- プロセスのまとめは、それぞれ `-Top` の件数まで表示します（`-Top` が 0 のときは 5 件）
  - 「CPU を多く使ったプロセス」は、期間全体の平均の高い順です。動いていなかった回は 0% として数えます（期間の途中で動き始めたプロセスや、終わったプロセスも、期間全体でどれだけ CPU を使ったかで比べるためです）
  - 「メモリを多く使ったプロセス」は、メモリ(MB) の最大の高い順です。「コミットの増減」は、最後に見たときのコミットから、最初に見たときのコミットを引いたものです。大きく増えているプロセスは、メモリリークを疑います
- 「目安を超えたところ」は、目安ごとに、超えた回数と、続けて超えた最も長い区間を表示します。1 回だけ超えたときは「1 回（14:21:40）」、何回か超えたが続けて超えたことはないときは「5 回（続けて超えたことはありません）」です。超えたところがなければ「目安を超えたところはありません」と表示します
- 条件によって、次の表と行も表示します
  - `-Process` を指定したとき：「■ 指定したプロセス（-Process）」に、当たったプロセスごとの CPU の平均と最大、メモリの最大、コミットの増減（20 件まで。表示しきれなかった分は「（ほか 3 件は process-list.csv を参照してください）」。`-NoSave` のときは「（ほか 3 件）」）
  - `-Counter` を指定したとき：「■ 追加のカウンター」に、カウンターとインスタンスごとの平均と最大（20 件まで。すべては `counters.csv` に記録します）
  - 想定していないエラーで止まったとき：1 行目の次に「※ エラーで止まりました: （理由）」。それまでの記録のまとめを表示し、保存します（終了コード 1）
- 「このツールの CPU 使用率」の後に、条件によって次の注意を表示します
  - `-Process` に当たるプロセスが、期間中に 1 つもなかった名前があるとき：「※ -Process に当たるプロセスは、期間中に見つかりませんでした: java」
  - 飛ばした回や記録しなかった回があったとき：「※ 間に合わずに飛ばした回 3 回・間があいて記録しなかった回 1 回（スリープから戻ったときなど）」
  - CSV を次のファイルに分けたとき：「※ system_2.csv に分けました（system.csv を開いているほかのプログラムがあり、書き足せなかったため）」（[保存されるファイル](#保存されるファイル)を参照）。`process-list.csv` を分けたときは「※ process-list.csv は、1,000,000 件ごとに process-list_2.csv などに分けました（Excel で開ける行数の上限のため）」
  - 記録の途中で保存できなくなったとき：「※ 14:30:05 から記録を保存できていません: （理由）」
  - 管理者として実行していないとき（保存するときだけ。実行ユーザーなどは `process-list.csv` にだけ書くため）：「※ 管理者として実行すると、ほかのユーザーのプロセスの実行ユーザー・実行ファイル・コマンドラインも記録できます」
- 1 回も記録しないうちに止めたときは、「1 回も記録しないうちに止めました」と表示し、まとめは表示しません

## 目安

次の値を超えたところに印を付けます（記録している間の行は `*`、終わったときのまとめは `※`）。目安は一般的によく使われる値で、サーバーの用途や機器によって、問題のない範囲は変わります。

| 項目 | 目安 | 考え方 |
| --- | --- | --- |
| CPU 使用率 | 90% 以上 | CPU に余裕がありません |
| プロセッサ待ち行列 | 論理プロセッサの数の 2 倍以上 | CPU が空くのを待っているスレッドが多い状態です |
| メモリ使用率 | 90% 以上 | すぐに使えるメモリが少なく、ページ ファイルを使い始めます |
| コミット率 | 90% 以上 | 上限に達すると、プログラムがメモリを確保できずに失敗します |
| ディスクの応答時間 | 20 ms 以上（その回の間に読み書きが 2 回以上あり、1 秒あたりの読み書きの回数 × 応答時間が 0.1 秒以上のときだけ） | 読み書きを待たされています。読み書きがほとんどないときは、1 回の遅い書き込みで大きな値になるため、判定しません。回数 × 応答時間は、1 秒のうちに読み書きを待っていた時間の合計（平均の待ち行列）です。遅くて回数をこなせないディスク（応答時間 130 ms で 1 秒に 8 回など）も判定に入ります |
| ディスクの空き | 10% 未満 | 空きが足りなくなりかけています |
| ネットワークの使用率 | 80% 以上 | 回線に余裕がありません |

- 「最も忙しいコア」と「ディスクの使用時間」には、目安を設けません。1 つのコアが短い時間 100% になるのはよくあることで、ディスクの使用時間は、SSD や RAID では 100% でも余裕があることがあるためです（ディスクが遅いかは、応答時間で判断してください）

## 保存されるファイル

記録を始めるときに、保存先に `Performance_<ホスト名>_<日時>` というフォルダを作り、次のファイルを保存します。

| ファイル | 内容 |
| --- | --- |
| `summary.txt` | 実行の条件と、終わったときのまとめ（1 回ごとの行は含めません。`system.csv` などにあります） |
| `system.csv` | CPU とメモリの記録 |
| `disks.csv` | ディスクの記録（1 回にドライブの数だけ行があります） |
| `network.csv` | ネットワークの記録（1 回にアダプターの数だけ行があります） |
| `processes.csv` | プロセスの記録（1 回に、上位と `-Process` で指定したプロセスの数だけ行があります） |
| `process-list.csv` | 期間中に見たすべてのプロセスの一覧と、期間中の平均・最大 |
| `counters.csv` | `-Counter` を指定したときだけ。追加のカウンターの記録 |

- `summary.txt` と `process-list.csv` 以外は、記録するたびに書き足します。途中で PC が止まっても、それまでの記録は残ります。`summary.txt` と `process-list.csv` は、終わったとき（`-Duration` の時間がたったか、Ctrl+C で止めたとき）に保存します
- 1 つの CSV の行が 100 万行に達したら、`processes_2.csv` のように次のファイルに分けて続けます（Excel で開ける行数の上限が約 105 万行のため）。`process-list.csv` も、100 万件を超えたら `process-list_2.csv` に分けます
- 記録している間に CSV を Excel などで開くと、そのプログラムが閉じるまで、ツールはその CSV に書き足せません。そのときは、`system_2.csv` のように次のファイルに分けて続けます（開いた CSV には、開いたときまでの記録があります）
- CSV とテキストは BOM 付き UTF-8 で保存します。保存先に書き込めないときは、記録を始める前にエラーで止まります（`-NoSave` を付ければ、画面で見るだけはできます）。記録の途中で書き込めなくなったとき（ディスクがいっぱいなど）は、警告を表示して保存をやめ、画面の表示だけで続けます（終了コード 1）
- ファイルの大きさの目安は、5 秒ごとの記録で 1 日あたり 30 MB ほどです（ドライブ・アダプターの数と `-Top` で変わります）

### CSV の列

| ファイル | 列 |
| --- | --- |
| `system.csv` | 日時、CPU 使用率(%)、最も忙しいコア(%)、プロセッサ待ち行列、メモリ使用率(%)、空きメモリ(MB)、コミット(MB)、コミットの上限(MB)、コミット率(%)、ページ読み込み(回/秒)、プロセス数 |
| `disks.csv` | 日時、ドライブ、使用時間(%)、応答時間(ms)、読み取りの応答時間(ms)、書き込みの応答時間(ms)、回数(回/秒)、読み取り(MB/秒)、書き込み(MB/秒)、待ち行列、空き(GB)、空き(%) |
| `network.csv` | 日時、アダプター、説明、受信(Mbps)、送信(Mbps)、使用率(%)、速度(Mbps) |
| `processes.csv` | 日時、プロセス、PID、CPU(%)、CPU の順位、メモリ(MB)、メモリの順位、コミット(MB)、I/O(MB/秒)、ハンドル数、スレッド数、指定、サービス |
| `process-list.csv` | プロセス、PID、サービス、実行ユーザー、起動日時、実行ファイル、コマンドライン、最初に見た日時、最後に見た日時、CPU の平均(%)、CPU の最大(%)、メモリの最大(MB)、コミットの最大(MB)、コミットの増減(MB) |
| `counters.csv` | 日時、カウンター、インスタンス、値 |

- 日時は `2026/11/24 14:05:17` の形で、実行した PC の時刻で書きます。Excel では日時として読み込まれるため、そのままグラフの横軸にできます
- 数値は `24,512.3` のように 3 桁区切りで書きます。小数は、応答時間(ms) が 2 桁、`counters.csv` の値が 3 桁まで、そのほかは 1 桁です
- 速度が分からないアダプター（速度が 0 のもの）は、使用率を空欄にします
- `processes.csv` の「CPU の順位」「メモリの順位」は、その回の、すべてのプロセスの中での順位です。「指定」は、`-Process` で指定した名前に当たるプロセスなら「はい」です
- `process-list.csv` は、CPU の平均の高い順です。CPU の平均は、期間全体の平均です（動いていなかった回は 0% として数えます）。実行ユーザー・起動日時・実行ファイル・コマンドラインは、そのプロセスを初めて見たときに調べます（取れなかったときは空欄です）
- `counters.csv` の「カウンター」は、`-Counter` に書いたとおりの名前です。インスタンスのないカウンターは、インスタンスを空欄にします
- 名前や値のうち、Excel で数式・数値・日付に変わる形のもの（`=` `+` `-` `@` で始まるものなど）は、`="..."` の形で書きます

### Excel でグラフにするとき

- `system.csv` を開き、「日時」の列と、見たい列（「CPU 使用率(%)」など）を選んで、「挿入」の「折れ線」を選びます
- `disks.csv`・`network.csv`・`processes.csv` は、1 回に複数の行があります。フィルターでドライブ・アダプター・プロセス（PID）を 1 つに絞ってから、グラフにしてください

## 追加のカウンター

`-Counter` で、CPU・メモリ・ディスク・ネットワーク以外のカウンターも一緒に記録できます。

| 見たいもの | カウンター |
| --- | --- |
| IIS の接続数 | `\Web Service(_Total)\Current Connections` |
| SQL Server のバッファー キャッシュの寿命 | `\SQLServer:Buffer Manager\Page life expectancy`（名前付きのインスタンスは `\MSSQL$<インスタンス名>:Buffer Manager\Page life expectancy`） |
| .NET のガベージ コレクションの時間 | `\.NET CLR Memory(*)\% Time in GC` |
| ページ ファイルの使用率 | `\Paging File(_Total)\% Usage` |

- `\オブジェクト(インスタンス)\カウンター` の形で、英語の名前で書きます。英語の名前で書けば、日本語の Windows でも英語の Windows でも、同じ書き方で記録できます。Microsoft のドキュメントや製品のマニュアルに載っている名前を、そのまま使えます
- この PC のパフォーマンス モニターに表示される名前で書いてもかまいません（英語の名前で見つからないときに、表示の名前として探します）
- インスタンスに `*` を書くと、そのときにあるすべてのインスタンスを記録します。記録の途中で増えたインスタンスも、その回から記録します
- 同じ名前のインスタンス（`\Process(*)\...` の `svchost` など）は、パフォーマンス モニターと同じように、2 つ目から `svchost#1`、`svchost#2` と番号を付けて区別します。番号はその回の並び順で付くため、途中でプロセスが終わると、番号と中身の組み合わせがずれることがあります（プロセスの値は、PID で見分ける `processes.csv` で見てください）
- 値は、カウンターの値のまま記録します（単位は変えません）
- 記録を始める前に、すべてのカウンターがあるかを確かめます。インスタンスを書いたカウンター（`(_Total)` など）は、そのインスタンスがあるかも確かめます。見つからないカウンターがあると、エラーで止まります
- ほかのコンピューターのカウンター（`\\SERVER02\...`）は書けません
- バッチファイルに書くときは、`%` を `%%` と書きます（`\Paging File(_Total)\%% Usage`。コマンドプロンプトの決まりです）。コマンドプロンプトに直接打つときと、設定ファイルに書くときは、`%` のままです

## 設定ファイル

同じ条件で繰り返し記録するときは、パラメーターを設定ファイルにまとめておけます。設定ファイルを使わなくても、パラメーターだけで動きます。

```ini
# Measure-Performance の設定ファイル
Interval = 30
Duration = 480
Process = w3wp
Process = java
Counter = \Web Service(_Total)\Current Connections
OutputFolder = \\fileserver\perf\%COMPUTERNAME%
```

- 書ける項目は、`Interval`、`Duration`、`Top`、`Process`、`Counter`、`OutputFolder`、`NoSave` です
- `Process` と `Counter` は、カンマで区切って 1 行に書いても、複数の行に分けて書いてもかまいません（すべての行を合わせて使います）。コマンドラインで指定すると、設定ファイルのものは使いません（両方を合わせることはしません）
- 設定ファイルに `OutputFolder` を書いていても、コマンドラインで `-NoSave` を付ければ、今回は保存せずに画面で見るだけにできます。設定ファイルに `NoSave = true` を書いていても、コマンドラインで `-OutputFolder` を指定すれば、今回は保存します（`powershell -File` では `-NoSave:$false` と書けないためです）。設定ファイルに両方を書くと、エラーで止まります
- `OutputFolder` に相対パスを書くと、設定ファイルのあるフォルダを基準にします
- そのほかの書き方と、書き間違いがあったときの動きは、[Get-DiskUsage の設定ファイル](../Get-DiskUsage/README.md#設定ファイル)と同じです

## タスクスケジューラで使うとき

決まった時間帯（夜間バッチの間など）に記録するときは、タスクスケジューラで起動できます。

- `-Duration` を必ず指定してください。タスクスケジューラの「終了」でツールを止めると、`summary.txt` と `process-list.csv` は保存されません（記録の CSV は残ります）
- タスクの「タスクを停止するまでの時間」（既定は 3 日）は、`-Duration` より長くしてください
- `-ConfigFile` と `OutputFolder` は、フルパスで指定してください。タスクスケジューラから実行すると、現在のフォルダが `C:\Windows\System32` になるためです

「操作」の設定は、次のようにします。

| 項目 | 値 |
| --- | --- |
| プログラム/スクリプト | `powershell.exe` |
| 引数の追加 | `-ExecutionPolicy Bypass -File C:\tools\Measure-Performance.ps1 -ConfigFile C:\tools\nightly.ini` |

## 終了コード

| 終了コード | 意味 |
| --- | --- |
| 0 | 記録を終えた（`-Duration` の時間がたったか、Ctrl+C で止めた）。目安を超えたところがあっても 0 です |
| 1 | 引数の誤りや、カウンターを読めないなどで止まった。記録の途中で保存できなくなった。または、想定していないエラーで記録の途中で止まった |

## 止まるとき

次の場合は、記録を始める前にエラーを表示して止まります（終了コード 1）。

| 場合 | 表示の例 |
| --- | --- |
| CPU やメモリのカウンターを読めない（性能カウンターが無効になっている、壊れているなど） | 「性能カウンターを読めません: \Processor Information(_Total)\% Processor Time（理由）」と、「性能カウンターが無効になっているか、壊れています。パフォーマンス モニターで表示できるかを確かめてください」 |
| `-Counter` のカウンターが見つからない（インスタンスを書いたときは、そのインスタンスがない場合も） | 「-Counter のカウンターが見つかりません: \Web Servce(_Total)\Current Connections（理由）」と、「英語の名前か、この PC のパフォーマンス モニターに表示される名前で書いてください」 |
| `-Counter` の書き方が違う | 「-Counter の書き方が違います: Processor(_Total)\% Processor Time（\オブジェクト(インスタンス)\カウンター の形で書いてください）」 |
| `-Counter` にほかのコンピューターのカウンターを書いた | 「-Counter には、ほかのコンピューターのカウンターは書けません: \\SERVER02\Memory\Available MBytes」 |
| `-Duration` が `-Interval` より短い | 「-Duration（1 分）が -Interval（300 秒）より短いため、1 回も記録できません」 |
| 入力をリダイレクトして起動した（Ctrl+C を受け取れない）のに、`-Duration` がない | 「Ctrl+C で止められない起動のしかたです。-Duration で記録する時間を指定してください」と、その理由 |
| コマンドラインで `-NoSave` と `-OutputFolder` を一緒に指定した | 「-NoSave のときは、-OutputFolder は指定できません」。設定ファイルに `NoSave = true` と `OutputFolder` を両方書いたときは、「設定ファイルの 3 行目と 5 行目: NoSave = true のときは、OutputFolder は書けません」と設定ファイルのパス |
| 値に `"` が残っている（コマンドプロンプトで `"C:\data\"` のように最後を `\"` にした。`-OutputFolder`・`-Process`・`-Counter`・`-ConfigFile` のどれでも。後ろに空白を含む値が続く場合も） | 「-OutputFolder の値に引用符（"）が残っています: …」と、正しい書き方 |
| どのパラメーターにも当たらない引数がある（パラメーターの名前の書き間違いなど） | 「どのパラメーターにも当たらない引数があります: -Intervl 10」 |
| 保存先に書き込めない | 「保存先に書き込めません: \\fileserver\perf（理由）」と、「-NoSave を付けると、画面に表示だけします」 |
| 設定ファイルの書き間違い | [Get-DiskUsage の設定ファイル](../Get-DiskUsage/README.md#書き間違いがあったとき)と同じ |
| Windows の API を呼ぶ準備ができない（`Add-Type` が使えない） | 「Windows の API を呼ぶ準備ができません。コンパイラーの実行が禁止されている環境では使えません」と、元のエラー |
| 制約付き言語モード（AppLocker や WDAC の環境） | 「制約付き言語モードでは使えません（AppLocker や WDAC でスクリプトの実行が制限されている環境です）」 |

- ディスクやネットワークのカウンターが読めないときは、止まらずに、その部分を飛ばして記録を続けます。「ディスク」の行の下に「※ ネットワークのカウンターを読めないため、記録しません（\Network Interface(*)\Bytes Received/sec: 理由）」のように表示します
- Ctrl+C は、次の記録を待っている間に受け付けます。記録の途中で押したときは、その回を記録し終えてから止まります。Ctrl+C で止めたときも、それまでの記録とまとめを保存します（途中で止めるのが通常の終わり方のため）
- 長い時間記録したあとは、まとめと `process-list.csv` を作るのに少し時間がかかることがあります（「まとめを作っています」と表示します）。その間にもう一度 Ctrl+C を押しても、保存が終わるまで止まりません

## 使うときの注意

- **記録できるのは、このツールを実行したコンピューターだけです。** ほかのサーバーを記録するときは、そのサーバーの上で実行してください
- **値は、間隔ごとの平均です。** 間隔より短い一瞬の負荷は、平均されて小さく見えます
- CPU 使用率は、パフォーマンス モニターと同じ値（`% Processor Time`）です。タスク マネージャーの CPU 使用率は、CPU のクロックの上がり下がりを含めた別の値（`% Processor Utility`）のため、ずれることがあります
- 仮想マシンの CPU 使用率は、仮想マシンの中から見た値です。ホストの CPU が足りずに待たされている時間は見えません。ホストの側でも確かめてください
- Hyper-V の動的メモリの仮想マシンでは、物理メモリの全体の量が、その時点で割り当てられている量になり、記録の途中でも変わります。メモリ使用率は、その時点の全体に対する割合です
- 管理者として実行しないと、ほかのユーザー（SYSTEM やサービスのアカウントを含む）のプロセスの実行ユーザー・実行ファイル・コマンドラインが取れないことがあります。使用率などの値と、サービスの名前は取れます
- このツールも、記録するたびに少し CPU を使います（終わったときに表示します）。`-Interval 1` で長い時間記録するときは、気を付けてください
- 長い時間記録するときは、保存先の空き容量に気を付けてください
- 性能カウンターが壊れていると、記録を始められません（[止まるとき](#止まるとき)を参照）。管理者のコマンドプロンプトで `lodctr /r` を実行すると直ることがあります（このツールは実行しません。システムの設定を作り直すため、実行する前に影響を確かめてください）
- `process-list.csv` のコマンドラインには、パスワードなどが含まれていることがあります。社外に出すときは中身を確かめてください

### カウンターの名前の言語について

パフォーマンス モニター・`Get-Counter`・`typeperf` は、カウンターを Windows の表示の言語の名前で指定する必要があり、ほかの言語の名前では読めません。日本語の Windows では、主なカウンター（`Processor`、`Memory` など）は英語の名前のままですが、新しい機能のカウンターの一部は日本語の名前になっています（`WMIPrvSE の正常性状態` など）。

このツールは、カウンターを英語の名前で読む Windows の仕組みを使うため、表示の言語によらず同じように動きます。`-Counter` も、英語の名前で書けます。

ただし、新しい形式のカウンターのうち、セットの名前が日本語になっているもの（`WMIPrvSE の正常性状態` など）は、日本語の Windows では英語の名前で見つからないことがあります。そのときは、パフォーマンス モニターに表示される名前で書いてください（英語の名前で見つからないときは、表示の名前として探します）。
