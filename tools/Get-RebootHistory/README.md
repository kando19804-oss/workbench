# Get-RebootHistory（再起動の履歴）

このサーバーが、いつ止まり・いつ起動したか、誰が・何の理由で再起動やシャットダウンをしたか、予期しない停止（ブルースクリーン・電源断など）がなかったかを、System ログから一覧にします。結果は画面に表示し、CSV にも保存します。

「夜中にサーバーが再起動していた。Windows Update か、誰かの操作か、ブルースクリーンか」を調べるときや、月次の報告で停止の回数と時間をまとめるときのための道具です。イベント ビューアーで、停止の指示（1074）・予期しない停止（6008・41）・起動の記録を 1 件ずつ突き合わせる手間を省きます。イベントログを変更・削除することはありません。

## 使い方

```powershell
# System ログに残っている、すべての停止と起動を一覧にする
powershell -ExecutionPolicy Bypass -File .\Get-RebootHistory.ps1
```

管理者でなくても使えます（System ログは、管理者でなくても読めます）。実行ポリシーなど、起動方法の詳しい説明は[リポジトリの README](../../README.md#使い方) を参照してください。

### 例

```powershell
# 障害の時間帯を指定する
powershell -ExecutionPolicy Bypass -File .\Get-RebootHistory.ps1 -Since "2026-11-10 22:00" -Until "2026-11-11 06:00"

# 直近 30 日の停止と起動を見る（月次の報告など）
powershell -ExecutionPolicy Bypass -File .\Get-RebootHistory.ps1 -Since 30d

# ほかのサーバーから集めた .evtx ファイルを読む
powershell -ExecutionPolicy Bypass -File .\Get-RebootHistory.ps1 -Path D:\collected\ap01
```

## パラメーター

| パラメーター | 内容 | 既定値 |
| --- | --- | --- |
| `-Since` | 期間の始め。停止か起動のどちらかが期間に入るものを取り出します。`"2026-11-10 09:00"` のような日時か、`2h`（2 時間前）・`30m`（30 分前）・`3d`（3 日前）のような今からの時間で書きます。書き方は [Search-Log の -Since](../Search-Log/README.md#パラメーター) と同じです | 指定なし（System ログに残っている、すべての記録） |
| `-Until` | 期間の終わり。書き方は `-Since` と同じです | 指定なし（今まで） |
| `-Path` | 読む .evtx ファイル、または .evtx ファイルのあるフォルダ（サブフォルダも探します）。カンマで区切って複数書けます。System ログの .evtx を読みます。指定すると、この PC のイベントログは読みません | 指定なし（この PC のイベントログを読む） |
| `-OutputFolder` | 結果の保存先 | スクリプトと同じフォルダ |
| `-NoSave` | 結果を保存せず、画面表示だけにします。`-OutputFolder` と一緒には使えません | なし |

- 設定ファイル（`-ConfigFile`）はありません。決まった条件で実行するときは、コマンドをバッチファイルに書いておいてください

```

```

表示の決まりは次のとおりです。

- 「停止と起動」は、停止 1 回を 1 行にして、新しい順に 20 件まで表示します。すべては `reboots.csv` に保存します。表示しきれなかった分は「（ほか 12 件は reboots.csv を参照してください）」のように表示します。`-NoSave` のときと、集めた後で保存に失敗したときは、すべて表示します
- 「停止」は OS が止まった時刻、「起動」は次に OS が起動した時刻、「停止時間」はその間の長さです（`0:06:40`、1 日を超えると `1日 2:03:00`）
- 画面の表の日時は、秒を省きます（表を 120 桁の画面に収めるためです。CSV には秒まで書きます）。「起動」は、停止と同じ日なら時刻だけ、違う日なら月日と時刻にします。年は付けません（年をまたいでも、停止の列の年と停止時間で分かります）。「停止」が「（不明）」のときも、月日と時刻です
- 停止のあとの起動の記録がないとき（止まったままのサーバーから写した .evtx を `-Path` で読んだときなど）は、「起動」を「（記録なし）」にします
- 「種類」は、「再起動」「シャットダウン」「予期しない停止」「不明」のいずれかです（[停止の種類](#停止の種類)を参照）
- 「ユーザー」は、再起動やシャットダウンを指示したユーザーです（停止の指示の記録があるときだけ）。指示のあと、停止の途中で止まった予期しない停止でも、指示したユーザーを書きます
- 「きっかけ・理由」は、次のように表示します
  - 再起動とシャットダウン：きっかけ（[停止を指示したプロセス](#停止を指示したプロセス)）と、コメント（`shutdown /c` やシャットダウン イベントの追跡ツールで入力したもの）。コメントがなければ、理由（「その他 (計画済)」など）
  - 予期しない停止：原因（[予期しない停止の原因](#予期しない停止の原因)を参照）。再起動やシャットダウンの途中で止まったときは、「再起動の途中で停止（Windows Update）: 不明（電源断・…）」のように、先に書きます（停止の記録はあるが、再起動かシャットダウンかが分からないときは「シャットダウンか再起動の途中で停止」）
  - 不明：「停止の記録がありません」など
- 停止の記録が残っていないなど、停止した時刻が分からないときは、「停止」を「（不明）」にし、「停止時間」を空欄にします
- 長い値は、ユーザーは半角 20 文字分、きっかけ・理由は半角 35 文字分で切り、最後を `…` にします（表を 120 桁の画面に収めるためです。CSV にはすべて書きます）
- 「今の起動」は、この PC を調べたときだけ表示します。OS の情報の最後の起動の時刻と、System ログのいちばん新しい起動の記録（OS の起動（12）か起動の種類（27））の、新しいほうです（高速スタートアップの起動は、OS の情報の最後の起動の時刻を変えないため）。稼働は、起動から今までの長さです
- `-Path` で複数のコンピューターの .evtx を読んだときは、表の最後にコンピューターの列を足します（この列の分、表が 120 桁を超えることがあります）
- 条件によって、次の行も表示します
  - `-Path` を指定したとき：「対象」の行が「対象: D:\collected\ap01\System.evtx ほか 1 ファイル」（読めたファイルの数です）
  - `-Since` を指定したとき：「期間」の行が「期間: 2026-10-18 21:00 ～ 2026-11-17 21:00（30 日）」
  - 期間の始めより前の記録が、もう System ログに残っていないとき：「※ 2026-08-02 10:15 より前の記録は、System ログに残っていません（上書きされています）」
  - 今の起動の記録が、System ログに残っていないとき（長く再起動していないサーバーなど）：「※ 今の起動（2026-03-01 02:10）の記録は、System ログに残っていません。それより前の停止は分かりません」
  - 最後の起動のあとに停止の指示があり、まだ止まっていないとき：「※ 2026-11-17 22:00 に再起動の指示（CORP\yamada）がありますが、まだ再起動していません」。`-Path` のときは「ログを書き出した時点で、まだ再起動していません」。`shutdown /a` で取り消した指示（取り消しの記録 1075 があるもの）は除きます
  - 期間の中に、System ログが消去された記録があるとき：「※ 2026-11-08 10:00 に System ログが消去されています（CORP\yamada）」
  - `-Path` で複数のコンピューターの .evtx を読んだときは、注意の先頭にコンピューターの名前を付けます（「※ SERVER01: 2026-08-02 10:15 より前の記録は…」）
  - 読めなかったログやファイルがあったとき：「スキップ 1 件（権限なし）」
- 期間の中に停止が 1 回もないときは「該当する停止はありません」と表示します

## 保存されるファイル

実行するたびに、保存先に `RebootHistory_<ホスト名>_<日時>` というフォルダを作り、次のファイルを保存します。

| ファイル | 内容 |
| --- | --- |
| `summary.txt` | 画面に表示した内容。一覧は 20 件を超えても省略しません |
| `reboots.csv` | 停止 1 回を 1 行にした一覧（停止の新しい順） |
| `events.csv` | 期間の中の、停止と起動に関わるすべての記録（新しい順） |
| `skipped.csv` | 読めなかったログやファイルと、その理由 |

CSV とテキストは BOM 付き UTF-8 で保存します。保存先に書き込めないときは、集め始める前にエラーで止まります（`-NoSave` を付ければ、画面に表示だけできます）。

### CSV の列

| ファイル | 列 |
| --- | --- |
| `reboots.csv` | 停止、起動、停止していた時間、その前の稼働時間、種類、Windows Update、きっかけ、ユーザー、理由、理由のコード、コメント、原因、停止コード、ダンプ、あとで入力した理由、停止の指示、プロセス、起動の種類、OS のバージョン、停止の前の最後の記録、備考、コンピューター |
| `events.csv` | 日時、操作、詳細、ユーザー、プロセス、イベント ID、ソース、コンピューター |
| `skipped.csv` | 理由、対象、詳細 |

- 日時は `2026/11/15 03:05:12` の形で、実行した PC の時刻で書きます
- `reboots.csv` の列の意味は次のとおりです
  - その前の稼働時間：前の起動から、この停止までの長さです。前の起動の記録が残っていないときは空欄です
  - Windows Update：Windows Update による停止なら「はい」（[Windows Update による停止](#windows-update-による停止)を参照）
  - きっかけ：停止を指示したプロセスを、分かる名前にしたものです。プロセスは、記録に書かれたプロセスのパスです
  - 理由・理由のコード・コメント：停止の指示（1074）に書かれた値です。理由は、記録を書いた OS の言語の文字のままです（英語の OS の .evtx なら英語です）
  - 原因・停止コード・ダンプ：予期しない停止のときに書きます。停止コードはブルースクリーンの停止コード（`0x0000003B` の形）、ダンプはメモリ ダンプを保存したパスです（記録に書かれたもので、今もあるとは限りません）
  - あとで入力した理由：Windows Server で、予期しない停止のあとにログオンした管理者が、シャットダウン イベントの追跡ツールに入力した理由とコメントです（1076）
  - 停止の指示：停止を指示した時刻です（1074。`shutdown /r /t 600` のように時間をおいた停止では、「停止」より前になります）
  - 起動の種類：「通常」か「高速スタートアップ」です
  - OS のバージョン：起動したときの OS のバージョンです（`10.0.20348.2340` の形）。前の起動から変わっていれば、「10.0.20348.2227 → 10.0.20348.2340」のように書きます。更新プログラムが入ったことが分かります
  - 停止の前の最後の記録：停止した時刻が分からないとき（「（不明）」）に、起動の前に System ログに書かれた最後の記録の時刻を書きます。停止した時刻の目安になります
  - 備考：次のようなことを書きます
    - 「再起動の途中で止まりました」（[停止の種類](#停止の種類)を参照）
    - 「停止の完了の記録がありません」
    - 「停止の記録がありません」
    - 「このあとの起動の記録がありません」
    - 「起動の記録が残っていないため、起動の時刻は OS の情報（最後の起動の時刻）から取りました」（この PC を調べたとき、最後の起動の記録が System ログに残っていないとき）
- `events.csv` の操作は、次のいずれかです：「停止の指示」（1074）「停止の取り消し」（1075）「停止の開始」（109）「イベントログの停止」（6006）「OS の停止」（13）「OS の起動」（12）「起動の種類」（27）「イベントログの起動」（6005）「予期しない停止」（6008）「正常に停止しないまま起動」（41）「ブルースクリーン」（1001）「理由の入力」（1076）「ログの消去」（104）
- 名前や値のうち、Excel で数式・数値・日付に変わる形のもの（`=` `+` `-` `@` で始まるものなど）は、`="..."` の形で書きます
- `skipped.csv` の理由は、「権限なし」「ログがない」「ファイルを読めない」「対象外のログ」（`-Path` で指定した、System ログでない .evtx）「リンク」（`-Path` のフォルダの下のジャンクションなど。たどりません）「その他のエラー」のいずれかです

## 判定のルール

### 読む記録

System ログの次の記録を読みます。

| 記録 | ソース | イベント ID |
| --- | --- | --- |
| 停止の指示（誰が・何の理由で） | User32 | 1074 |
| 停止の取り消し（`shutdown /a`） | User32 | 1075 |
| 予期しない停止の理由の入力（Windows Server） | User32 | 1076 |
| 停止の開始（再起動かシャットダウンか） | Microsoft-Windows-Kernel-Power | 109 |
| OS の停止 | Microsoft-Windows-Kernel-General | 13 |
| イベントログの停止 | EventLog | 6006 |
| OS の起動 | Microsoft-Windows-Kernel-General | 12 |
| 起動の種類（高速スタートアップかどうか） | Microsoft-Windows-Kernel-Boot | 27 |
| イベントログの起動 | EventLog | 6005 |
| 予期しない停止 | EventLog | 6008 |
| 正常に停止しないまま起動 | Microsoft-Windows-Kernel-Power | 41 |
| ブルースクリーン | Microsoft-Windows-WER-SystemErrorReporting | 1001 |
| ログの消去 | Microsoft-Windows-Eventlog | 104 |

- ソースとイベント ID の絞り込みは、イベントログの側で行うため、記録の多いログでも速く取り出せます。メッセージ（イベント ビューアーの説明の文）は組み立てずに、記録の値だけを読みます
- 時刻は、記録の値の中の時刻（OS の起動・停止の時刻、予期しない停止の時刻）を使います。予期しない停止（6008）の説明の文の日時は、地域の設定で書式が変わり、見えない文字も入るため使わず、記録の中の UTC の時刻を使います
- 停止のときの記録（OS の停止など）は、次の起動のあとにまとめて書かれるため、記録の番号の順と時刻の順が一致しません。記録は時刻の順に並べて組み合わせます

### 停止と起動の組み合わせ

- OS の起動（12）を区切りにして、起動と起動の間の記録から、その間の停止を決めます。12 の記録が 1 件もないコンピューターは、イベントログの起動（6005）を区切りにします。同じ起動の記録は 1 つにまとめます
- 12 の記録があるコンピューターで、12 のないイベントログの起動（6005）が次の形のときは、イベントログのサービスだけを再起動したもの（OS は再起動していない）とみなします。その 6005 と、直前のイベントログの停止（6006）は、停止と起動に数えず、`events.csv` の詳細に「イベントログのサービスの再起動（OS は再起動していません）」と書きます
  - 6006 から 1 分の内の 6005 で、間に OS の停止（13）と停止の開始（109）がない（OS を再起動すると、間にこの 2 つが入ります）。6006 がないとき（サービスが落ちたとき）は、前の起動のあとに停止の指示（1074）・停止の開始・OS の停止がない
  - 6005 の前後に、予期しない停止（6008）と正常に停止しないまま起動（41）がない
  - この形でない 6005 は、壊れた .evtx などで 12 だけが読めなかった起動として、6005 で補います。起動の種類（27）が残っていれば、その時刻を起動の時刻にします
- 「停止」の時刻は、OS の停止（13）、イベントログの停止（6006）、停止の開始（109）、停止の指示（1074）の順に、残っているものを使います。予期しない停止のときは、6008 に記録された時刻を使います。6008 がなければ、OS の停止・イベントログの停止・停止の開始の順に使います（停止の指示の時刻は使いません。時間をおいた指示のあと、ずっと後で止まったこともあるためです）。どれもなければ「（不明）」です
- 停止していた時間と稼働していた時間は、秒の端数を切り捨てた時刻で計算します（CSV の時刻から計算した長さと合うように）
- 「起動」の時刻は、OS の起動（12）に記録された時刻を使います
- 起動と起動の間に停止の指示（1074）が複数あるときは、取り消し（1075）のない、最後のものを使います。それより前のものと、取り消した指示は、`events.csv` にだけ書きます
- 予期しない停止（6008）・正常に停止しないまま起動（41）・ブルースクリーン（1001）・理由の入力（1076）は、起動したあとに書かれるため、書かれた時刻の直前の起動の、その前の停止のものとして扱います。OS の起動（12）がなく、イベントログの起動（6005）で補った起動は、6005 が OS の起動より遅れて書かれるため、1 分前を起動の時刻とみなして割り当てます
- System ログに残っている最初の起動より前の停止は、停止の記録が残っているときだけ表示します

### 停止の種類

| 種類 | 判定 |
| --- | --- |
| 予期しない停止 | 停止のあとの起動で、予期しない停止（6008）・正常に停止しないまま起動（41）・ブルースクリーン（1001）・予期しない停止の理由の入力（1076）のどれかが記録されている。停止の指示のあとで止まったとき（シャットダウンの途中で応答しなくなり、電源を切ったときなど）も、こちらにして、備考に「再起動の途中で止まりました」「シャットダウンの途中で止まりました」のように書きます |
| 再起動 | 停止の開始（109）が再起動。109 がないときは、停止の指示（1074）の種類が再起動 |
| シャットダウン | 停止の開始（109）がシャットダウンか電源を切る。109 がないときは、停止の指示（1074）の種類がシャットダウンか電源を切る |
| 不明 | 上のどれでもない。停止の記録がまったくないまま起動しているとき（備考は「停止の記録がありません」）と、停止の記録はあるが再起動かシャットダウンかが分からないとき |

- 停止の指示（1074）の種類は、記録を書いた OS の言語の文字で入っています。日本語と英語の OS の文字（「再起動」「restart」など）を読みます
- 停止の指示はあるが、OS の停止とイベントログの停止の記録がなく、次の起動で予期しない停止も記録されていないときは、指示の種類で再起動かシャットダウンにし、備考に「停止の完了の記録がありません」と書きます。次の起動が高速スタートアップのときは書きません（高速スタートアップでシャットダウンすると、OS を完全には止めないため、OS の停止とイベントログの停止は記録されません）
- この PC を調べたときに、最後の起動の記録のあとに停止の記録があるとき（最後の起動の記録が残っていないとき）は、OS の情報の最後の起動の時刻が停止より後なら、それを起動の時刻にします。そうでなければ、その停止は行にしません（今動いているので、止まったままではないため）

### 停止を指示したプロセス

「きっかけ」には、停止の指示（1074）に書かれたプロセスを、次のように書きます。

| プロセス | きっかけ |
| --- | --- |
| `StartMenuExperienceHost.exe` | スタート メニュー |
| `shutdown.exe` | shutdown コマンド |
| `TrustedInstaller.exe`、`MoUsoCoreWorker.exe`、`usoclient.exe`、`wuauclt.exe` | Windows Update |
| `wlms.exe` | 評価版の期限切れ（評価版の Windows Server は、ライセンスの期限が切れると 1 時間ごとにシャットダウンします） |
| `wmiprvse.exe` | WMI（Restart-Computer など）（`Restart-Computer` や `Rename-Computer -Restart` などで再起動したとき。理由は「この理由のタイトルが見つかりません」になります） |
| そのほか | プロセスのファイル名（`winlogon.exe`、`svchost.exe` など） |

### Windows Update による停止

次のどちらかに当たる停止を、Windows Update による停止とします（`reboots.csv` の「Windows Update」が「はい」、画面の合計の「うち Windows Update」に数えます）。

- 停止を指示したプロセスが、上の表の Windows Update のもの
- 理由のコードが、「オペレーティング システム」の「アップグレード」「サービス パック」「修正プログラム」「セキュリティ修正」のどれか（手で更新プログラムを入れて、その理由を選んで再起動したときも含みます）

どの更新プログラム（KB）が入ったかは、停止の記録には書かれていないため、表示しません。`reboots.csv` の「OS のバージョン」が変わっていれば、その起動で更新プログラムが入っています。

### 予期しない停止の原因

| 原因 | 判定 |
| --- | --- |
| ブルースクリーン | 41 の停止コードが 0 でないか、ブルースクリーン（1001）の記録がある。「ブルースクリーン 0x0000003B（SYSTEM_SERVICE_EXCEPTION）」のように、停止コードを書きます（よく出る停止コードには名前を添えます） |
| 電源ボタンの長押し | 41 に、電源ボタンを押した記録がある |
| スリープの途中で停止 | 41 に、スリープに入る途中だった記録がある |
| 不明（電源断・フリーズ・強制的な電源オフなど） | 上のどれでもない |

- Windows Server で、予期しない停止のあとに管理者が理由を入力したとき（1076）は、`reboots.csv` の「あとで入力した理由」に書き、画面の「きっかけ・理由」にも「入力された理由: UPS の故障 ／ 不明（電源断・…）」のように、原因より先に書きます（コメントがなければ理由）

### 読めないとき

- この PC の System ログを読めないとき（権限がないときなど）は、エラーで止まります（終了コード 1。[止まるとき](#止まるとき)を参照）
- `-Path` のファイルのうち、壊れているものや読めないものは飛ばして、`skipped.csv` に残します（途中で壊れているときは、読めたところまでを結果に含めます）。System ログを 1 件も読めなかったときは、エラーで止まります。同じファイルを重ねて指定したとき（ファイルと、それを含むフォルダなど）は、1 回だけ読みます
- `-Path` で複数のコンピューターの .evtx を読んだときは、コンピューターごとに組み合わせます。どのコンピューターのログかは、ファイルごとに、いちばん新しい記録に書かれた名前で決めます

## 終了コード

| 終了コード | 意味 |
| --- | --- |
| 0 | 期間の中に、停止があった |
| 2 | 期間の中に、停止がなかった |
| 1 | 引数の誤りや、System ログを読めなかったなどで、止まった |

## 止まるとき

次の場合は、エラーを表示して止まります（終了コード 1）。

| 場合 | 表示の例 |
| --- | --- |
| System ログを読む権限がない | 「System ログを読む権限がありません」と、「管理者として実行してください。ほかの PC から集めた .evtx ファイルは、-Path で読めます」 |
| `-Since` や `-Until` の書き方が違う、`-Since` が `-Until` より後 | 「-Since の日時を読めません: 2026-13-01」 |
| `-NoSave` と `-OutputFolder` を一緒に指定した | 「-NoSave のときは、-OutputFolder は指定できません」 |
| 値に `"` が残っている（コマンドプロンプトで `"C:\data\"` のように最後を `\"` にした。`-Path`・`-OutputFolder`・`-Since`・`-Until` のどれでも。後ろに `-Since "2026-11-12 09:00"` のような空白を含む値が続く場合も） | 「-OutputFolder の値に引用符（"）が残っています: …」と、正しい書き方 |
| どのパラメーターにも当たらない引数がある（パラメーターの名前の書き間違いなど） | 「どのパラメーターにも当たらない引数があります: -Sinse 30d」 |
| 保存先に書き込めない | 「保存先に書き込めません: \\fileserver\reboot（理由）」と、「-NoSave を付けると、画面に表示だけします」 |
| `-Path` のファイルをすべて読めなかった | 「読める .evtx ファイルがありません」と、ファイルごとの理由（見つからない、権限なし、形式が違うなど） |
| `-Path` に System ログの .evtx がない | 「-Path に、System ログの .evtx がありません」 |
| 停止と起動の記録を 1 件も読めなかった（先頭は読めるが、停止と起動の記録より前で壊れている .evtx だけを指定したなど。先頭から壊れている .evtx だけなら、上の「読める .evtx ファイルがありません」になります） | 「System ログを読めませんでした」と、ファイルごとの理由 |
| 制約付き言語モード（AppLocker や WDAC の環境） | 「制約付き言語モードでは使えません（AppLocker や WDAC でスクリプトの実行が制限されている環境です）」 |

集めた後で保存に失敗したとき（ディスクがいっぱいなど）は、警告を表示し、画面の表示だけで終わります（終了コード 1）。途中で中断（Ctrl+C）した場合は、結果を保存しません。

## 使うときの注意

- **イベントログの保存できる大きさを超えると、古い記録から消えていきます。** 画面の「System ログ: … から残っています」で、どこまでさかのぼれるかを確かめてください。System ログの既定の大きさ（20 MB）では、数週間から数か月分です
- **予期しない停止の時刻は、OS が最後に動いていたと記録した時刻です。** 電源断やフリーズでは、実際に止まった時刻と少しずれることがあります
- **停止の記録がまったく残らないことがあります。** 突然の電源断などで、停止の記録も予期しない停止の記録もないまま起動していることがあります。その停止は「不明」として表示します
- 高速スタートアップ（Windows 10 / 11 の既定）が有効な PC でシャットダウンすると、OS を完全には起動し直しません。その起動は、`reboots.csv` の起動の種類を「高速スタートアップ」にします。「再起動」を選んだときは、いつも完全に起動し直します
- スリープと休止状態は、再起動ではないので含めません（休止状態からの再開も含めません）
- Hyper-V の仮想マシンを、ホストから「電源オフ」で止めると、仮想マシンの中では予期しない停止として記録されます
- 期間は、実行した PC の時刻で解釈します。ほかのサーバーの .evtx を読むときに、そのサーバーと時間帯の設定が違うと、表示する日時もずれます
- 結果には、停止を指示したユーザーの名前とコメントが入ります。社外に出すときは中身を確かめてください
