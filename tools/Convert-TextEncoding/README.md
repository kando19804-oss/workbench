# Convert-TextEncoding（文字コード判定・変換）

フォルダの中のテキストファイルについて、文字コード（UTF-8・Shift_JIS など）と改行（CRLF・LF）を判定し、一覧にします。指定すれば、確認したうえで、まとめて変換します。

「Shift_JIS と UTF-8 のファイルが混ざっていないか確かめたい」「Mac や Linux で作られた LF のファイルを、CRLF にそろえたい」「古いバッチやログを UTF-8 にそろえたい」というときのための道具です。

- 既定では判定するだけで、ファイルを変更しません
- 変換するときは、件数を表示して確認を求めます。元のファイルは、結果のフォルダに控えます

## 使い方

```powershell
# 判定するだけ（ファイルは変更しない）
powershell -ExecutionPolicy Bypass -File .\Convert-TextEncoding.ps1 -Path D:\scripts

# UTF-8（BOM あり）・改行 CRLF にそろえる（確認してから変換する）
powershell -ExecutionPolicy Bypass -File .\Convert-TextEncoding.ps1 -Path D:\scripts -To UTF8BOM -LineEnding CRLF
```

実行ポリシーなど、起動方法の詳しい説明は[リポジトリの README](../../README.md#使い方) を参照してください。

### 例

```powershell
# CSV だけを調べる
powershell -ExecutionPolicy Bypass -File .\Convert-TextEncoding.ps1 -Path D:\data -Filter "*.csv"

# 拡張子にかかわらず、すべてのファイルを調べる（バイナリは判定で飛ばす）
powershell -ExecutionPolicy Bypass -File .\Convert-TextEncoding.ps1 -Path D:\data -Filter "*"

# 改行だけを LF にそろえる（文字コードは変えない）
powershell -ExecutionPolicy Bypass -File .\Convert-TextEncoding.ps1 -Path D:\share\linux -LineEnding LF

# Shift_JIS にそろえる。一部のフォルダは除く
powershell -ExecutionPolicy Bypass -File .\Convert-TextEncoding.ps1 -Path D:\old -To SJIS -Exclude "*\archive"

# 確認せずに変換する（タスクスケジューラなど、画面を見ずに実行するとき）
powershell -ExecutionPolicy Bypass -File .\Convert-TextEncoding.ps1 -Path D:\inbox -To UTF8BOM -Force
```

## パラメーター

| パラメーター | 内容 | 既定値 |
| --- | --- | --- |
| `-Path` | 調べるフォルダかファイル。フォルダを指定すると、サブフォルダも含めて調べます | 現在のフォルダ |
| `-Filter` | 調べるファイルの名前の条件。ワイルドカード（`*` と `?`）で、`"*.csv,*.txt"` のようにカンマで区切って書けます。`-Path` にファイルを直接指定したときは使いません | [よくあるテキストの拡張子](#既定で調べるファイル) |
| `-Exclude` | 調べないフォルダやファイル。フルパスに対して、ワイルドカード（`*`）で指定します。書き方は [Get-DiskUsage の -Exclude](../Get-DiskUsage/README.md#パラメーター) と同じです | 指定なし |
| `-To` | 変換後の文字コード。`UTF8BOM`（UTF-8・BOM あり）、`UTF8`（UTF-8・BOM なし）、`SJIS`（Shift_JIS）のどれかです | 指定なし（文字コードは変えない） |
| `-LineEnding` | 変換後の改行。`CRLF` か `LF` です | 指定なし（改行は変えない） |
| `-Force` | 確認せずに変換します | なし |
| `-OutputFolder` | 結果の保存先 | スクリプトと同じフォルダ |
| `-NoSave` | 結果を保存せず、画面表示だけにします。変換するとき（`-To` か `-LineEnding` を指定したとき）は使えません（元のファイルを控えられないため） | なし |

`-To` と `-LineEnding` のどちらも指定しないときは、判定だけを行います。

### 既定で調べるファイル

`-Filter` を指定しないときは、次の拡張子のファイルを調べます。

```
*.txt, *.csv, *.tsv, *.log, *.ini, *.cfg, *.conf, *.xml, *.json, *.yml, *.yaml, *.md,
*.htm, *.html, *.css, *.js, *.sql, *.ps1, *.psm1, *.psd1, *.bat, *.cmd, *.vbs, *.sh, *.py
```

## 画面の表示例

判定だけのとき：

```
文字コード判定・変換 (Convert-TextEncoding 1.0.0)
対象: D:\scripts（既定の拡張子）   2026-11-01 15:00:00   PC01

■ 文字コードと改行の内訳
 文字コード          改行   件数
 UTF-8（BOM あり）   CRLF     32
 Shift_JIS           CRLF     18
 UTF-8（BOM なし）   LF        5
 ASCII のみ          CRLF     40
 バイナリ            -         2

■ ファイル（文字コードの順）
 文字コード          改行   サイズ      ファイル
 Shift_JIS           CRLF    12.3 KB   D:\scripts\backup.bat
 UTF-8（BOM なし）   LF       3.1 KB   D:\scripts\tool\run.ps1
 ...

ファイル 97 件  所要 0.4秒
保存先: C:\tools\TextEncoding_PC01_20261101_150000
```

変換するとき（`-To UTF8BOM -LineEnding CRLF`）は、判定の結果の後に次のように表示し、確認を求めます。

```
■ 変換の予定（UTF-8（BOM あり）・CRLF にそろえる）
変換するファイル 23 件
  Shift_JIS → UTF-8（BOM あり）  18 件
  改行 LF → CRLF                  5 件
変換しないファイル 74 件（すでに同じ 72 件・対象外 2 件）
元のファイルは、保存先の backup フォルダに控えます
変換しますか？ [Y] はい  [N] いいえ: Y

結果: 変換しました  23 件  失敗 0 件  所要 1.2秒
保存先: C:\tools\TextEncoding_PC01_20261101_150000
```

表示の決まりは次のとおりです。

- 内訳は、件数の多い順に並べます。ファイルの一覧は、文字コード・改行・パスの順に並べます
- 画面に表示するファイルは 200 件までです。超えた分は「（ほか 1,234 件は files.csv を参照してください）」と表示します。`-NoSave` のときと、保存先のフォルダを作れなかったときは、すべて表示します
- 変換するファイルがないときは「変換するファイルはありません（すべてそろっています）」と表示し、確認せずに終わります。変換できないファイルがあるときは、「（すべてそろっています）」を付けません
- 確認で `N` を入力したときは「変換しませんでした」と表示し、判定の結果だけを保存します
- 条件によって、次の行も表示します
  - `-Exclude` を指定したとき：「除外: *\archive」。除外したものがあれば「除外 3 件」
  - 読めないフォルダやファイルがあったとき：「スキップ 3 件（権限なし 2・その他のエラー 1）」
  - リンクがあったとき：「たどらなかったリンク 1 件」
  - 変換の予定に、日本語などを含む `.ps1`・`.psm1`・`.psd1` を BOM なしの UTF-8 にするものがあるとき：「※ .ps1 を BOM なしの UTF-8 にすると、Windows PowerShell 5.1 で日本語が化けます（3 件）」
  - 変換の予定に、日本語などを含む `.bat`・`.cmd` を UTF-8 にするものがあるとき：「※ .bat・.cmd を UTF-8 にすると、コマンドプロンプトで日本語が化けます（2 件）」

## 保存されるファイル

実行するたびに、保存先に `TextEncoding_<ホスト名>_<日時>` というフォルダを作り、次のファイルを保存します。

| ファイル | 内容 |
| --- | --- |
| `summary.txt` | 画面に表示した内容（条件・内訳・一覧・変換の結果）。一覧は 200 件を超えても省略しません |
| `files.csv` | 調べたファイルの一覧と、変換の結果 |
| `skipped.csv` | 調べられなかったフォルダ・ファイルと、その理由 |
| `backup\` | 変換したファイルの、変換する前のファイル。調べたフォルダと同じ構成で控えます（`D:\scripts\tool\run.ps1` なら `backup\tool\run.ps1`）。変換したときだけ作ります |

CSV とテキストは BOM 付き UTF-8 で保存します。保存先に書き込めないときは、判定だけのときは警告を表示して画面表示だけで終わり、変換するときは変換せずに止まります（元のファイルを控えられないため）。

### CSV の列

| ファイル | 列 |
| --- | --- |
| `files.csv` | ファイル、文字コード、改行、サイズ(バイト)、最終更新日時、結果、備考 |
| `skipped.csv` | 理由、パス、詳細 |

- 文字コードは「UTF-8（BOM あり）」「UTF-8（BOM なし）」「UTF-16（BOM あり）」「Shift_JIS」「ASCII のみ」「EUC-JP」「JIS」「バイナリ」「判定できない」のどれかです
- 改行は「CRLF」「LF」「CR」「混在」「なし」（改行が 1 つもない）のどれかです。バイナリなど、判定できないときは空欄です
- 結果は、判定だけのときは空欄です。変換するときは「変換した」「すでに同じ」「対象外」「変換できない」「失敗」「変換しなかった」（確認で `N` を選んだ）のどれかです
- 備考には、変換しなかった理由や、変換の内容（`Shift_JIS → UTF-8（BOM あり）・改行 LF → CRLF`）を書きます
- サイズと最終更新日時は、変換したファイルは変換した後の値です
- サイズは 3 桁区切りで出力します
- `skipped.csv` の理由は、「権限なし」「リンク」「除外指定」「クラウドのみ」「その他のエラー」のいずれかです

## 判定のルール

ファイルを最後まで読んで、次の順に判定します。

| 順 | 条件 | 判定 |
| --- | --- | --- |
| 1 | 先頭が UTF-8 の BOM（EF BB BF） | UTF-8（BOM あり）。BOM の後が UTF-8 として正しくなければ、判定できない |
| 2 | 先頭が UTF-16 の BOM（FF FE か FE FF） | UTF-16（BOM あり）。BOM の後が UTF-16 として正しくなければ、判定できない |
| 3 | 先頭の 8 KB に NUL（値が 0 のバイト）がある | バイナリ（BOM のない UTF-16 もここに入ります） |
| 4 | JIS のエスケープ（ESC $ B など）がある | JIS |
| 5 | すべて ASCII の文字（値が 0x80 未満） | ASCII のみ |
| 6 | UTF-8 として正しい | UTF-8（BOM なし） |
| 7 | Shift_JIS として正しく、EUC-JP として読んだほうが自然でない | Shift_JIS |
| 8 | EUC-JP として正しく、Shift_JIS として読むと半角カナばかりになる | EUC-JP |
| 9 | どれでもない | 判定できない |

- 「ASCII のみ」のファイルは、UTF-8 としても Shift_JIS としても同じ内容です
- 短いファイルは、UTF-8 と Shift_JIS の両方として正しいことがあります。そのときは UTF-8 を優先します（Shift_JIS の日本語が、たまたま UTF-8 として正しくなることは、まれなためです）
- 100 MB を超えるファイルは、先頭の 1 MB だけで判定し、備考に「先頭の 1 MB で判定」と書きます。このファイルは変換しません
- PowerShell 7 で実行すると、NEC 選定 IBM 拡張文字など、Shift_JIS の中で同じ文字が 2 か所にある字の一部（`∵` の 879A・FA5B など）を含むファイルは、「判定できない」になり、変換しません（7 の Shift_JIS の読み方の違いのためです。Windows PowerShell 5.1 では Shift_JIS と判定します）
- OneDrive などのクラウドのみのファイルは、読むとダウンロードが始まるため、調べずに `skipped.csv` に「クラウドのみ」として残します
- 改行は、CR LF の組を CRLF、CR のない LF を LF、LF のない CR を CR として数え、1 種類だけなら その名前、2 種類以上あれば「混在」とします

## 変換のルール

- 変換するのは、文字コードが「UTF-8（BOM あり／なし）」「UTF-16（BOM あり）」「Shift_JIS」「ASCII のみ」のファイルだけです。「EUC-JP」「JIS」「バイナリ」「判定できない」と、先頭だけで判定した大きなファイルは「対象外」とし、変換しません
- `-To` だけを指定したときは、改行はそのままです。`-LineEnding` だけを指定したときは、文字コードはそのままです（BOM の有無も変えません）
- 改行が「混在」のファイルは、`-LineEnding` を指定すれば、すべて指定した改行にそろえます
- `-To SJIS` のとき、Shift_JIS にない文字（絵文字や、一部の漢字・記号など）を含むファイルは「変換できない」とし、変換しません。備考に、最初に見つかった文字と行番号を書きます（例: `Shift_JIS にない文字: 🙂（12 行目）`）
- 変換するときは、ほかのプログラムが書き込めないようにファイルを開いたまま、読む・控える・書く・読み直すまでを行います。変換の予定を立てた後に（確認を待っている間などに）中身が変わったファイルは、書き足された分を消さないよう、変換せずに「失敗」とします
- 元のファイルは、変換する前に `backup\` に控えます。控えられなかったファイルは、変換しません
- Shift_JIS のまま改行だけを変えるときは、文字に直さず、バイトのまま改行を置き換えます（Shift_JIS には同じ文字になる字が 2 か所にあるものがあり、文字に直してから戻すと、バイトが変わってしまうためです）
- 変換した後に読み直し、元の文字と同じ内容になっているかを確かめます。違っていたときは、控えたファイルで元に戻し、「失敗」とします
- ファイルのアクセス権と属性（隠しなど）は変えません。読み取り専用のファイルは、変換せずに「変換できない」とします
- 最終更新日時は、変換した日時になります（バックアップや同期のツールが、変わったファイルとして扱えるように）
- 変換をやり直したいときは、`backup\` のファイルを元の場所にコピーして戻してください

## そのほかのルール

- ジャンクションやシンボリックリンクはたどりません
- 権限がなくて読めないフォルダやファイルは飛ばして、件数を表示し、`skipped.csv` に残します
- このツールの結果のフォルダ（`TextEncoding_*`）の中は調べません（控えたファイルを、次に調べてしまわないように）
- 260 文字を超える長いパスや、名前に `[` `]` を含むフォルダ・ファイルも扱えます
- 途中で中断（Ctrl+C）した場合は、判定の途中なら結果を保存しません。変換の途中なら、それまでに変換したファイルはそのまま残り、控えと結果も残します。書き込みの途中だったファイルは「失敗」とし、備考に「backup のファイルから戻してください」と書きます

## 終了コード

| 終了コード | 意味 |
| --- | --- |
| 0 | 判定できた。変換したときは、すべて変換できた（確認で `N` を選んだときも 0） |
| 1 | 引数の誤りなどで止まった。または、変換できなかった・失敗したファイルがある |

## タスクスケジューラで使うとき

- 変換するときは `-Force` を付けてください。付けないと、確認できないため変換せずに止まります
- `-Path` と `-OutputFolder` は、フルパスで指定してください

## 使うときの注意

- **.ps1 は BOM ありの UTF-8 か Shift_JIS にしてください。** BOM なしの UTF-8 にすると、Windows PowerShell 5.1 は Shift_JIS として読むため、日本語が化けます
- **.bat・.cmd は Shift_JIS のままにしてください。** コマンドプロンプトは、ファイルを Shift_JIS（コードページ 932）として読みます
- CSV を UTF-8 にするときは、BOM ありにしてください。BOM なしだと、Excel が Shift_JIS として開き、日本語が化けます
- 文字コードの判定は、内容から推測するものです。ごく短いファイルや、日本語の少ないファイルは、誤って判定することがあります。変換する前に、`files.csv` で判定の結果を確かめてください
