# Search-EventLog（イベントログ抽出）

指定した期間のイベントログから、エラーなどのイベントを取り出し、どのイベントが何回出ているかを集計します。結果は画面に表示し、CSV にも保存します。

「障害が起きた時間帯に、どんなエラーが出ていたかをまとめて見たい」「夜間に何か起きていないかを毎朝確かめたい」というときのための道具です。イベント ビューアーで 1 件ずつ開いて見る手間を省きます。ほかのサーバーから集めた .evtx ファイルも読めます。イベントログを変更・削除することはありません。

## 使い方

```powershell
# 直近 24 時間の、System と Application の重大・エラーを取り出す
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1
```

実行ポリシーなど、起動方法の詳しい説明は[リポジトリの README](../../README.md#使い方) を参照してください。

### 例

```powershell
# 障害の時間帯を指定する
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1 -Since "2026-10-31 22:00" -Until "2026-11-01 02:00"

# 直近 7 日の、警告も含めて取り出す
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1 -Since 7d -Level "Critical,Error,Warning"

# 特定のイベント ID だけを取り出す（サービスの異常終了）
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1 -Since 30d -Id "7031,7034"

# いつも出ていて気にしなくてよいイベントを除く
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1 -ExcludeId "10016,36887"

# メッセージに「timeout」か「タイムアウト」を含むイベントだけを取り出す
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1 -Since 3d -Pattern "timeout|タイムアウト"

# アプリのログ（ソースを指定）
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1 -LogName Application -Source "MSSQLSERVER"

# Security ログ（管理者として実行してください）
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1 -LogName Security -Level "Information" -Id 4625

# ほかのサーバーから集めた .evtx ファイルを読む
powershell -ExecutionPolicy Bypass -File .\Search-EventLog.ps1 -Path D:\collected\ap01_System.evtx -Since 3d
```

## パラメーター

| パラメーター | 内容 | 既定値 |
| --- | --- | --- |
| `-LogName` | 読むイベントログの名前。`"System,Application"` のようにカンマで区切って書けます。`Microsoft-Windows-TaskScheduler/Operational` のような、アプリケーションとサービスのログも指定できます | `System,Application` |
| `-Path` | 読む .evtx ファイル、または .evtx ファイルのあるフォルダ（サブフォルダも探します）。カンマで区切って複数書けます。指定すると、`-LogName` は使いません | 指定なし（この PC のイベントログを読む） |
| `-Since` | この日時以降のイベントを取り出します。`"2026-10-31 09:00"` のような日時か、`2h`（2 時間前）・`30m`（30 分前）・`3d`（3 日前）のような今からの時間で書きます。書き方は [Search-Log の -Since](../Search-Log/README.md#パラメーター) と同じです | `24h`（直近 24 時間） |
| `-Until` | この日時までのイベントを取り出します。書き方は `-Since` と同じです | 指定なし（今まで） |
| `-Level` | 取り出すレベル。`Critical`（重大）、`Error`（エラー）、`Warning`（警告）、`Information`（情報）、`Verbose`（詳細）を、カンマで区切って書きます。日本語（`"重大,エラー,警告"`）でも書けます | `Critical,Error` |
| `-Id` | 取り出すイベント ID。`"7031,7034"` のようにカンマで区切って書けます | 指定なし（すべての ID） |
| `-ExcludeId` | 除くイベント ID。カンマで区切って書けます | 指定なし |
| `-Source` | 取り出すソース（イベント ビューアーの「ソース」）。カンマで区切って書けます | 指定なし（すべてのソース） |
| `-Pattern` | メッセージにこの文字を含むイベントだけを取り出します。`"timeout\|タイムアウト"` のように `\|` で区切ると、どれかを含むものを取り出します。書いた文字のまま探し、大文字と小文字は区別しません | 指定なし |
| `-OutputFolder` | 結果の保存先 | スクリプトと同じフォルダ |
| `-NoSave` | 結果を保存せず、画面表示だけにします | なし |

- 期間・レベル・ID の絞り込みは、イベントログの側で行うため、イベントが多いログでも速く取り出せます。`-Source`・`-ExcludeId`・`-Pattern` は、取り出した後に絞り込みます（`-Source` をイベントログの側で絞ると、この PC にないソースを指定したときにエラーになり、ほかのサーバーの .evtx を読めないためです）
- 設定ファイル（`-ConfigFile`）はありません。毎朝の確認など、決まった条件で実行するときは、コマンドをバッチファイルに書いておいてください

```

■ 集計（件数の多い順・上位 30）
 件数  レベル  ログ         ソース                   ID    最後に発生        メッセージ（1 行目）
   42  エラー  System       Service Control Manager  7031  2026-11-01 14:10  Print Spooler サービスは予期せぬ原因により終了しました。…
    9  エラー  Application  Application Error        1000  2026-11-01 13:55  障害が発生しているアプリケーション名: app.exe、…
    2  重大    System       Kernel-Power             41    2026-11-01 09:02  システムは正常にシャットダウンする前に再起動しました。…

■ 新しい順（20 件まで）
 日時                 レベル  ログ    ソース                   ID    メッセージ（1 行目）
 2026-11-01 14:10:03  エラー  System  Service Control Manager  7031  Print Spooler サービスは予期せぬ原因により終了しました。…
 ...

イベント 53 件（重大 2・エラー 51）  種類 3  所要 2.1秒
保存先: C:\tools\EventLog_SERVER01_20261101_150000
```

表示の決まりは次のとおりです。

- 集計は、ログ・レベル・ソース・イベント ID が同じものを 1 つにまとめ、件数の多い順に 30 件まで表示します。メッセージは、いちばん新しいイベントの 1 行目です
- 新しい順の一覧は、20 件まで表示します。すべてのイベントは `events.csv` に保存します。`-NoSave` のときと、保存先のフォルダを作れなかったときは、集計も一覧もすべて表示します
- メッセージは、画面では 1 行目だけを、80 文字までにして表示します
- 重大の行は赤、エラーの行は黄色で表示します
- イベントが 1 件もないときは「該当するイベントはありません」と表示します
- 条件によって、次の行も表示します
  - `-Path` を指定したとき：「対象」の行が「対象: D:\collected\ap01_System.evtx ほか 2 ファイル」
  - `-Id`・`-ExcludeId`・`-Source`・`-Pattern` を指定したとき：「条件: ID 7031, 7034・除く ID 10016・ソース MSSQLSERVER・メッセージ timeout | タイムアウト」
  - 読めなかったログやファイルがあったとき：「スキップ 1 件（権限なし）」
  - メッセージを取得できなかったイベントがあったとき：「メッセージを取得できなかったイベント 3 件」
  - 管理者として実行しておらず、読めなかったログがあったとき：「※ 管理者として実行すると、Security などのログも読めます」

## 保存されるファイル

実行するたびに、保存先に `EventLog_<ホスト名>_<日時>` というフォルダを作り、次のファイルを保存します。

| ファイル | 内容 |
| --- | --- |
| `summary.txt` | 画面に表示した内容（条件・集計・件数）。集計は 30 件を超えても省略しません |
| `events.csv` | 取り出したすべてのイベント（新しい順） |
| `summary.csv` | ログ・レベル・ソース・イベント ID ごとの集計（件数の多い順） |
| `skipped.csv` | 読めなかったログやファイルと、その理由 |

CSV とテキストは BOM 付き UTF-8 で保存します。保存先に書き込めないときは警告を表示し、画面表示だけで終了します。

### CSV の列

| ファイル | 列 |
| --- | --- |
| `events.csv` | 日時、ログ、レベル、イベントID、ソース、タスクのカテゴリ、コンピューター、ユーザー、メッセージ |
| `summary.csv` | 件数、レベル、ログ、ソース、イベントID、最初に発生、最後に発生、メッセージ（1 行目） |
| `skipped.csv` | 理由、対象、詳細 |

- 日時は `2026/11/01 14:10:03` の形で、実行した PC の時刻で書きます
- レベルは「重大」「エラー」「警告」「情報」「詳細」のどれかです
- メッセージは全文を書きます（改行もそのまま入ります。Excel ではセルの中で改行されます）。Excel の 1 つのセルに入る長さ（32,000 文字）を超える分は切ります
- メッセージを取得できないイベントは、「（メッセージを取得できません）」と書きます
- ユーザーは、イベントに記録されたユーザーの名前です（ないときは空欄です）
- メッセージのうち、Excel で数式・数値・日付に変わる形のもの（`=` `+` `-` `@` で始まるものなど）は、`="..."` の形で書きます
- `skipped.csv` の理由は、「権限なし」「ログがない」「ファイルを読めない」「その他のエラー」のいずれかです

## 取り出しのルール

- `-LogName` に書いたログのうち、この PC にないものや、権限がなくて読めないものは飛ばして、`skipped.csv` に残します。ほかのログは読みます。すべて読めなかったときは、エラーで止まります（終了コード 1）
- 「情報」には、レベルが 0（Security ログの監査イベントなど）のイベントも含めます
- メッセージは、この PC にあるソースの情報を使って組み立てます。ソースのアプリが入っていないと、メッセージを取得できません（イベント ビューアーで「説明が見つかりません」と出るものです）
- .evtx ファイルを読むときも、メッセージはこの PC にあるソースの情報で組み立てます。ほかのサーバーにしかないアプリのイベントは、メッセージを取得できないことがあります。そのときは、そのサーバーの上で実行してください
- イベントがとても多いとき（数十万件など）は、メッセージの組み立てに時間がかかります。期間やレベルで絞ってください

## 終了コード

| 終了コード | 意味 |
| --- | --- |
| 0 | 該当するイベントがあった |
| 2 | 該当するイベントがなかった |
| 1 | 引数の誤りや、すべてのログを読めなかったなどで、止まった |

毎朝の確認をタスクスケジューラで動かし、「終了コードが 0 なら担当者に知らせる」といった使い方ができます。

## 使うときの注意

- **Security ログを読むには、管理者として実行してください。** System と Application は、管理者でなくても読めます
- 期間は、実行した PC の時刻で解釈します。ほかのサーバーの .evtx を読むときに、そのサーバーと時間帯の設定が違うと、表示する日時もずれます
- イベントログの保存できる大きさ（既定では 20 MB など）を超えると、古いイベントから消えていきます。古い期間を指定しても、イベントが残っていないことがあります
