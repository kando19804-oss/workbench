# Get-PortProcess（ポート使用プロセス特定）

指定したポートを使っているプロセスを突き止めます。ポートを指定しなければ、このコンピューターで待ち受けているすべてのポートを一覧にします。結果は画面に表示し、CSV にも保存します。

「サービスを起動しようとしたら、ポートが使用中で起動できない」「このポートで待ち受けているのは何のプログラムか」「作業の前後で、待ち受けているポートを記録しておきたい」というときのための道具です。読み取りだけを行い、プロセスを止めたり設定を変えたりすることはありません。

## 使い方

```powershell
powershell -ExecutionPolicy Bypass -File .\Get-PortProcess.ps1 -Port 8080
```

実行ポリシーなど、起動方法の詳しい説明は[リポジトリの README](../../README.md#使い方) を参照してください。

### 例

```powershell
# 待ち受けているすべてのポートを一覧にする
powershell -ExecutionPolicy Bypass -File .\Get-PortProcess.ps1

# 8080 番と 443 番を使っているプロセスを調べる
powershell -ExecutionPolicy Bypass -File .\Get-PortProcess.ps1 -Port "8080,443"

# 範囲で指定する
powershell -ExecutionPolicy Bypass -File .\Get-PortProcess.ps1 -Port "8000-8100"

# 待ち受けに加えて、接続中の通信も調べる（どのプロセスが DB サーバーの 1433 番につないでいるか、など）
powershell -ExecutionPolicy Bypass -File .\Get-PortProcess.ps1 -Port 1433 -Established

# 結果を保存せず、画面表示だけにする
powershell -ExecutionPolicy Bypass -File .\Get-PortProcess.ps1 -Port 8080 -NoSave
```

## パラメーター

| パラメーター | 内容 | 既定値 |
| --- | --- | --- |
| `-Port` | 調べるポート。`"80,443,8000-8100"` のように、カンマと範囲（`-`）で書けます。1～65535 で指定します | 指定なし（すべてのポート） |
| `-Established` | TCP の待ち受けに加えて、接続中などの通信（待ち受け以外の状態）も出します | なし（TCP は待ち受けだけ） |
| `-OutputFolder` | 結果の保存先 | スクリプトと同じフォルダ |
| `-NoSave` | 結果を保存せず、画面表示だけにします | なし |
| `-ConfigFile` | 設定ファイルのパス（[設定ファイル](#設定ファイル)を参照）。コマンドラインで指定した値は、設定ファイルより優先します | 指定なし |

- `-Port` は、ローカルのポートかリモートのポートのどちらかが一致すれば対象にします。`-Established` と一緒に使うと、「このコンピューターから、ほかのサーバーの 1433 番につないでいるプロセス」も見つけられます
- UDP は、待ち受け・接続中の区別がないため、`-Established` に関係なく常に出します

## 画面の表示例

```
ポート使用プロセス特定 (Get-PortProcess 1.0.0)
対象: SERVER01   2026-10-31 15:10:00   管理者: はい
条件: ポート 443, 8080   TCP は待ち受けのみ
該当 3 件（プロセス 2 個）

■ ポート
 プロトコル  ローカル      状態      PID   プロセス    サービス
 TCP         0.0.0.0:443   待ち受け     4  System      （カーネル：HTTP.sys や SMB など）
 TCP         0.0.0.0:8080  待ち受け  5124  java.exe    Tomcat9
 TCP         [::]:8080     待ち受け  5124  java.exe    Tomcat9

■ プロセス
  PID  プロセス  実行ユーザー                 起動日時          実行ファイル
    4  System    NT AUTHORITY\SYSTEM          2026-10-28 08:01
 5124  java.exe  NT AUTHORITY\LOCAL SERVICE   2026-10-30 22:14  C:\Program Files\Apache\Tomcat9\bin\tomcat9.exe

保存先: C:\tools\PortProcess_SERVER01_20261031_151000
```

- `-Established` を指定したときは、「ローカル」の後ろに「リモート」の列を表示します
- 状態は、「待ち受け」「接続中」と、それ以外の TCP の状態名（`TimeWait`、`CloseWait` など）のどれかです。UDP は「-」です
- サービスは、そのプロセスで動いている Windows のサービスの名前です。svchost.exe のように 1 つのプロセスで複数のサービスが動いているときは、3 つまで表示し、残りは「ほか 5 個」とします。CSV には、すべて書きます
- PID 4（System）は、Windows のカーネルです。IIS などが使う HTTP.sys や、ファイル共有（SMB）の待ち受けは、PID 4 に見えます。サービスの列に注記を表示します
- PID 0 は、切断の後始末をしている通信（`TimeWait` など）で、実際に通信しているプロセスはありません。プロセスの列には Windows が付けている名前「System Idle Process」を表示し、サービスの列に「（切断の後始末：プロセスなし）」と注記します
- `-Established` を指定すると、`Bound` という状態の行が出ることがあります。接続の準備のためにポートを確保しただけの状態で、リモートは `0.0.0.0:0` と表示されます
- 調べている間に終わったプロセスは、プロセスの列に「（終了したプロセス）」と表示します
- 該当がないときは「該当なし」と表示します。`-Port` に指定したポートが空いていることの確認にも使えます
- コマンドラインは、パスワードなどが含まれることがあるため、画面には表示せず、CSV にだけ書きます
- 条件によって、次の行も表示します
  - `-ConfigFile` を指定したとき：「条件」の前の行に「設定ファイル: C:\tools\port.ini」
  - 管理者として実行しておらず、取れなかった情報があったとき：「※ 管理者として実行すると、ほかのユーザーのプロセスの実行ユーザー・実行ファイル・コマンドラインも取れます（コマンドラインは CSV にだけ書きます）」

## 保存されるファイル

実行するたびに、保存先に `PortProcess_<ホスト名>_<日時>` というフォルダを作り、次のファイルを保存します。

| ファイル | 内容 |
| --- | --- |
| `summary.txt` | 画面に表示した内容 |
| `ports.csv` | ポートごとの一覧（画面の「ポート」と同じ並び）。プロセスの情報も各行に付けます |

CSV は BOM 付き UTF-8 で保存するため、Excel でダブルクリックすればそのまま開けます。保存先に書き込めないときは警告を表示し、画面表示だけで終了します。

### CSV の列

| ファイル | 列 |
| --- | --- |
| `ports.csv` | プロトコル、ローカルアドレス、ローカルポート、リモートアドレス、リモートポート、状態、PID、プロセス、サービス、実行ユーザー、起動日時、実行ファイル、コマンドライン |

- サービスは、複数あるときは `, ` で区切って、すべて書きます。PID 4 と PID 0 の行には、画面と同じ注記を書きます
- 管理者でないために取れなかった値は、空欄にします
- 起動日時は `2026/10/30 22:14:05` の形で書きます

## 並び順

プロトコル（TCP、UDP の順）、ローカルポートの番号の順、ローカルアドレスの順に並べます。

## 設定ファイル

同じ条件で繰り返し調べるときは、パラメーターを設定ファイルにまとめておけます。設定ファイルを使わなくても、パラメーターだけで動きます。

```ini
# Get-PortProcess の設定ファイル
Port = 80, 443, 1433, 3389
Established = false
OutputFolder = \\fileserver\evidence\%COMPUTERNAME%
```

- 書ける項目は、`Port`、`Established`、`OutputFolder`、`NoSave` です。`Established` と `NoSave` は `true` か `false` で書きます
- `Port` は、複数の行に分けて書けます（すべての行を合わせて使います）。書き方が誤っているときは、その行の番号を表示して止まります
- そのほかの書き方と、書き間違いがあったときの動きは、[Get-DiskUsage の設定ファイル](../Get-DiskUsage/README.md#設定ファイル)と同じです

## 情報の取り方と注意

- ポートの一覧は、Windows に最初から入っている `Get-NetTCPConnection` と `Get-NetUDPEndpoint` で取ります。プロセスとサービスの情報は、CIM（`Win32_Process`、`Win32_Service`）で取ります。どちらも Windows Management Instrumentation（WMI）のサービスを使うため、このサービスが止まっていると動きません
- 実行ユーザーは、`Get-Process -IncludeUserName` でまとめて取ります。Windows PowerShell 5.1 では管理者でないとこの方法を使えないため、実行ファイルが取れたプロセスについてだけ、CIM の `GetOwner` で 1 つずつ取ります
- ポートの一覧とプロセスの情報は、少しずれた時刻に取ります。その間にプロセスが終わったり、ポートを閉じたりすることがあります
- 管理者として実行しないと、ほかのユーザー（SYSTEM やサービスのアカウントを含む）のプロセスの実行ユーザー・実行ファイル・コマンドラインが取れないことがあります。PID とプロセス名、サービス名は取れます
- 終了コードは、調べ終わったら 0、引数の誤りや一覧を取れなかったときは 1 です。該当がなくても 0 です
