# Get-FolderPermission（アクセス権一覧）

共有フォルダとその中のフォルダについて、誰に・どんな権限が付いているかを、共有のアクセス許可と NTFS のアクセス権の両方から一覧にし、CSV に残します。継承を切っているところ、個人を直接指定しているところ、削除されたアカウントが残っているところなど、確かめたほうがよいところに印を付けます。

「ファイルサーバーを引き継いだが、どのフォルダに誰が入れるのか分からない」「サーバーを移す前に、今のアクセス権を記録しておきたい」「監査で、共有フォルダのアクセス権の一覧を求められた」「ある人だけ、フォルダを開けない」というときのための道具です。

- 読むだけで、アクセス権を変更することはありません
- 親のアクセス権を継承しているだけのフォルダは、親と同じなので一覧に出しません。アクセス権を変えてあるフォルダだけを出すので、大きなファイルサーバーでも短い一覧になります（`-All` を付けると、すべてのフォルダを出します）

## 使い方

```powershell
# ファイルサーバーの上で、この PC の共有フォルダをすべて調べる
powershell -ExecutionPolicy Bypass -File .\Get-FolderPermission.ps1

# 指定したフォルダを調べる
powershell -ExecutionPolicy Bypass -File .\Get-FolderPermission.ps1 -Path D:\share\営業
```

実行ポリシーなど、起動方法の詳しい説明は[リポジトリの README](../../README.md#使い方) を参照してください。

### 例

```powershell
# クライアントから、サーバーの共有フォルダをすべて調べる
powershell -ExecutionPolicy Bypass -File .\Get-FolderPermission.ps1 -Path \\fs01

# サーバーの共有フォルダを 1 つだけ調べる
powershell -ExecutionPolicy Bypass -File .\Get-FolderPermission.ps1 -Path \\fs01\営業

# アクセス権に出てくるグループのメンバーも調べる
powershell -ExecutionPolicy Bypass -File .\Get-FolderPermission.ps1 -ExpandGroup

# ファイルだけに付けたアクセス権も探す
powershell -ExecutionPolicy Bypass -File .\Get-FolderPermission.ps1 -Path D:\share\営業 -IncludeFile

# 3 階層までのすべてのフォルダのアクセス権を記録する（サーバーを移す前の記録など）
powershell -ExecutionPolicy Bypass -File .\Get-FolderPermission.ps1 -Path D:\share -All -Depth 3

# 結果を保存せず、画面表示だけにする
powershell -ExecutionPolicy Bypass -File .\Get-FolderPermission.ps1 -NoSave
```

## パラメーター

| パラメーター | 内容 | 既定値 |
| --- | --- | --- |
| `-Path` | 調べるフォルダ。この PC のフォルダ、共有フォルダ（`\\fs01\営業`）、ネットワークドライブ（`Z:\`）を指定できます。`\\fs01` のようにサーバー名だけを書くと、そのサーバーの共有フォルダをすべて調べます。複数指定するときは、`"D:\share\営業,D:\share\総務"` のようにカンマで区切って 1 つの文字列にします。指定した文字列全体が 1 つのフォルダとして存在するときは、カンマを含む名前のフォルダとして扱います | この PC の共有フォルダすべて（[調べる共有フォルダ](#調べる共有フォルダ)を参照） |
| `-Depth` | 何階層下まで調べるか。`-Path` の直下が 1 です。1～100 で指定します | すべての階層 |
| `-All` | アクセス権を変えていないフォルダも含めて、すべてのフォルダのアクセス権を出します | なし（変えてあるフォルダだけ） |
| `-IncludeFile` | ファイルも調べて、アクセス権を変えてあるファイルを出します（[一覧に出すもの](#一覧に出すもの)を参照）。ファイルの数だけ時間がかかります | なし（フォルダだけ） |
| `-ExpandGroup` | アクセス権に出てくるグループのメンバーを調べて、`groups.csv` に出します（[グループのメンバー](#グループのメンバー)を参照） | なし |
| `-Exclude` | 調べないフォルダやファイル。ワイルドカード（`*`）で、カンマで区切って書きます。書き方は [Find-DuplicateFile の除外の書き方](../Find-DuplicateFile/README.md#除外の書き方)と同じです | 指定なし |
| `-OutputFolder` | 結果の保存先 | スクリプトと同じフォルダ |
| `-NoSave` | 結果を保存せず、画面表示だけにします | なし |

`-Path` と `-OutputFolder` には、`%TEMP%` のような環境変数を書けます。タスクスケジューラなど、コマンドプロンプトを通らずに起動されて、環境変数が展開されないまま届くときも、ツールの中で展開します。

`-Path` を指定したときは、「対象」の行に指定したフォルダを表示します（`\\fs01` のときは「\\fs01（共有フォルダ 5 件）」）。`-Depth` を指定したときは、「階層: 3 階層下まで」の行も表示します。

表示の決まりは次のとおりです。

- 「フォルダ」は調べたフォルダの数、「アクセス権を変えてあるフォルダ」はそのうち、継承を切っているか、アクセス権を追加しているか、継承が親と合わないフォルダの数です（`-Path` のフォルダや共有フォルダのフォルダも、変えていなければ数えません）。`-IncludeFile` のときは、「ファイル」と「アクセス権を変えてあるファイル」も表示します
- 「共有フォルダ」には、調べたフォルダにつながる共有フォルダと、その共有のアクセス許可を表示します（[調べる共有フォルダ](#調べる共有フォルダ)を参照）。つながる共有がないときは「（このフォルダにつながる共有フォルダはありません）」と表示します。共有のアクセス許可を読めなかった共有は、アカウントの代わりに「（読めません: アクセスが拒否されました。）」のように理由を表示します
- 「アクセス権を変えてあるフォルダ」には、フォルダごとに、継承の状態（継承を切っている・継承が親と合わない・追加している・継承だけ。アクセス権の設定（DACL）そのものがないときは「アクセス権の設定がない」）と、そのフォルダで設定したアクセス権を表示します。親から継承した分は、`permissions.csv` に出します。そのフォルダが共有フォルダのときは、「（共有: 営業）」と書き添えます。アクセス権が 1 つもない（だれにも許可していない）ときは、「（だれにも許可していません）」と表示します
  - `-Path` に指定したフォルダと共有フォルダのフォルダは、変えていなくても必ず表示します。このときは、親から継承した分も「許可（継承）」のように表示します（ここから下の基準になるため）。継承が親と合わないフォルダも、継承した分を表示します
  - `-All` のときは、見出しを「■ フォルダのアクセス権（すべてのフォルダ）」にして、変えていないフォルダも「継承だけ」として表示します。`-IncludeFile` のときの見出しは「■ アクセス権を変えてあるフォルダとファイル」です
  - 画面に表示するのは 20 フォルダまでです。超えた分は「（ほか 15 フォルダは permissions.csv を参照してください）」（`-IncludeFile` のときは「ほか 15 件は」）と表示します。`-NoSave` のときと、保存先のフォルダを作れなかったときは、すべて表示します
  - 確かめたほうがよいところに当てはまる行には、最後に「★個人を直接指定」のように印を付けます
- 「確かめたほうがよいところ」には、[確かめたほうがよいところ](#確かめたほうがよいところ)の種類ごとの件数と、例を 3 つまで表示します。当てはまるものがない種類は表示しません。どれもないときは「確かめたほうがよいところはありません」と表示します
- 条件によって、次の行も表示します
  - `-Exclude` を指定したとき：「除外: keep, *\old」
  - 調べなかったフォルダやファイル（`-Exclude` に当てはまったもの、ごみ箱、`System Volume Information`）があったとき：「除外 3 件」
  - 読めないフォルダがあったとき：「スキップ 3 件（権限なし 2・その他のエラー 1）」
  - リンクがあったとき：「たどらなかったリンク 1 件」
  - `-ExpandGroup` を指定したとき：「■ グループのメンバー」の見出しの下に「グループ 8 件  メンバー 57 件（groups.csv を参照してください）」。調べられなかったグループがあれば、その名前と理由。メンバーの一覧は `summary.txt` に書きます（`-NoSave` のときは画面に表示します）
  - 管理者として実行しておらず、読めないフォルダや共有のアクセス許可があったとき：「※ 管理者として実行すると、読める範囲が広がります」
  - 共有フォルダ越しに調べて、共有フォルダのフォルダで親から継承した設定を見分けられなかったとき：「※ 共有フォルダのフォルダで、親から継承した設定を見分けられなかったものがあります（\\fs01\営業）。…」（[共有フォルダを調べるとき](#共有フォルダを調べるとき)を参照）

## 保存されるファイル

実行するたびに、保存先に `FolderPermission_<ホスト名>_<日時>` というフォルダを作り、次のファイルを保存します。

| ファイル | 内容 |
| --- | --- |
| `summary.txt` | 画面に表示した内容。一覧は 20 件を超えても省略しません |
| `shares.csv` | 共有フォルダと、共有のアクセス許可 |
| `folders.csv` | 一覧に出したフォルダ（`-IncludeFile` のときはファイルも）ごとの、継承の状態・所有者・確かめたほうがよいところ |
| `permissions.csv` | 一覧に出したフォルダ（ファイル）のアクセス権。親から継承した分も含めて、1 つの設定を 1 行にします |
| `groups.csv` | グループのメンバー。`-ExpandGroup` を指定したときだけ作ります |
| `skipped.csv` | 調べられなかったフォルダ・ファイル・共有と、その理由 |

CSV とテキストは BOM 付き UTF-8 で保存します。保存先に書き込めないときは、警告を表示して、画面表示だけで終わります。保存の途中で書き込めなくなったときは、書きかけの結果のフォルダを消してから、警告を表示します。

### CSV の列

| ファイル | 列 |
| --- | --- |
| `shares.csv` | サーバー、共有名、フォルダ、説明、種類、アカウント、アカウントの種類、アクセス許可、値、SID、備考 |
| `folders.csv` | パス、種類、階層、継承、直接の設定、継承した設定、所有者、共有名、注意 |
| `permissions.csv` | パス、種類、階層、継承、許可・拒否、アカウント、アカウントの種類、アクセス権、適用先、設定した場所、詳細、値、注意、SID |
| `groups.csv` | グループ、メンバー、メンバーの種類、経由、状態、SID、備考 |
| `skipped.csv` | 理由、パス、詳細 |

- `shares.csv` の「フォルダ」は、サーバーの上のフォルダ（`D:\share\営業` など）です。「種類」は「許可」か「拒否」です。共有のアクセス許可を読めなかった共有と、だれにも許可していない共有は、1 行だけ出して、備考に理由を書きます
- 「種類」（`folders.csv`・`permissions.csv`）は「フォルダ」か「ファイル」です
- 「階層」は、`-Path`（共有フォルダ）のフォルダが 0、その直下が 1 です
- 「継承」は「あり」か「切っている」です
- 「直接の設定」はそのフォルダで設定したアクセス権の数、「継承した設定」は親から継承したアクセス権の数です
- 「共有名」は、そのフォルダが共有フォルダのときの共有名です
- 「設定した場所」は「このフォルダ」（ファイルのときは「このファイル」）か「親から継承」です
- 「詳細」は、アクセス権が「特殊」のときに、中身（「属性の読み取り、アクセス許可の読み取り」など）を並べます
- 「値」は、アクセス権を `0x001301BF` の形の 16 進数で出します（ほかのツールや資料と突き合わせるとき用）
- 「注意」は、[確かめたほうがよいところ](#確かめたほうがよいところ)の種類を、当てはまるだけ「・」でつないで書きます
- 「経由」は、入れ子のグループを通して入っているメンバーのときに、「グループ」の列のグループから、そのメンバーが入っているグループまでの間のグループを、「CORP\営業1課 → CORP\営業1課第2班」のように書きます。直接のメンバーは空欄です
- 「状態」は、ユーザーのアカウントが無効になっているときに「無効」と書きます
- `skipped.csv` の理由は、「権限なし」「リンク」「除外指定」「その他のエラー」のいずれかです
- 件数は 3 桁区切りで出力します

## 一覧に出すもの

既定では、次のフォルダを一覧に出します。

- `-Path` に指定したフォルダ（`-Path` を省略したときは、各共有フォルダのフォルダ）
- 共有フォルダになっているフォルダ
- **継承を切っている**フォルダ（エクスプローラーの「継承の無効化」をしたもの）
- **アクセス権を追加している**フォルダ（継承はしたまま、そのフォルダでアクセス権を足したもの）
- **継承が親と合わない**フォルダ（[継承が親と合わないフォルダ](#継承が親と合わないフォルダ)を参照）

親のアクセス権を継承しているだけのフォルダは、親と同じなので出しません。`-All` を指定すると、`-Depth` までのすべてのフォルダを出します。

### 継承が親と合わないフォルダ

フォルダを同じドライブの中で移動すると（エクスプローラーでのドラッグ、`move` コマンドなど）、アクセス権は移動する前のまま残ります。前の親から継承した設定も、「継承」の印が付いたまま残るため、エクスプローラーで見ても、今の親から継承しているように見えます。たとえば、人事のフォルダから共有のフォルダへ移したフォルダには、人事のフォルダのアクセス権が残っています。

このツールは、親のアクセス権から「子が継承するはずの権限」を作り、子が継承している権限と比べます。違っていれば「継承が親と合わない」とし、継承している設定も一覧に出して、確かめたほうがよいところに数えます。

- 比べるのは、子に効く権限と、さらに下へ渡す権限の中身です。Windows が設定の書き方をまとめたり分けたりしても（同じ権限が重なっているときなど）、中身が同じなら「合っている」とします
- `CREATOR OWNER` から子に効く設定は、あってもなくても合っているとします（子を作ったときにだけでき、後から親の変更が伝わったときにはできないことがあるため）。この設定は子を作った人の SID で作られ、所有者を後から変えても残るため、SID は問いません（1 つまで）
- ストアのアプリなどの SID（`S-1-15-` で始まるもの）は比べません（アプリが作ったフォルダでは、Windows が特別な継承をするため）
- 直すときは、エクスプローラーの「セキュリティ」→「詳細設定」で、親のフォルダの「子オブジェクトのアクセス許可エントリすべてを、このオブジェクトからの継承可能なアクセス許可エントリで置き換える」を使うか、`icacls <フォルダ> /reset /t` を実行します（どちらも、そのフォルダより下で直接付けた設定も消えます。先に、この一覧で確かめてください）

`-IncludeFile` を指定すると、ファイルも調べて、継承を切っているファイル、アクセス権を追加しているファイル、継承が親と合わないファイルを出します。ファイルは、`-All` を指定しても、アクセス権を変えてあるものだけを出します（すべてのファイルを出すと、一覧が大きくなりすぎるため）。

所有者が変わっているだけのフォルダは出しません（所有者は `folders.csv` の列で分かります）。

### アクセス権の名前

アクセス権には、エクスプローラーの「セキュリティ」タブと同じ区切りで名前を付けます。

| 名前 | 中身 |
| --- | --- |
| フル コントロール | すべての操作 |
| 変更 | 読み取り・書き込み・削除（アクセス権の変更と所有権の取得はできない） |
| 読み取りと実行 | 読み取りと、プログラムの実行（フォルダをたどること） |
| フォルダの内容の一覧表示 | 「読み取りと実行」と同じ中身を、フォルダにだけ適用したもの |
| 読み取り | 一覧・ファイルの読み取り・属性とアクセス権の読み取り |
| 書き込み | ファイルとフォルダの作成・書き込み・属性の書き込み |
| 読み取りと書き込み | 「読み取り」と「書き込み」の両方 |
| 読み取りと実行・書き込み | 「読み取りと実行」と「書き込み」の両方（「変更」から削除を除いたもの） |
| 特殊 | 上のどれにも当たらない組み合わせ。中身を「詳細」の列に並べます |

`CREATOR OWNER` などに付く汎用のアクセス権（GENERIC_ALL など）は、ファイルとフォルダのアクセス権に直してから名前を付けます。共有のアクセス許可は、「フル コントロール」「変更」「読み取り」のどれか（当たらないものは「特殊」）です。

### 適用先

| 適用先 | 意味 |
| --- | --- |
| このフォルダだけ | このフォルダだけに効く |
| このフォルダ・サブフォルダ・ファイル | このフォルダと、中のすべてのフォルダとファイルに効く（いちばん多い形） |
| このフォルダ・サブフォルダ | ファイルには効かない |
| このフォルダ・ファイル | 中のフォルダには効かない |
| サブフォルダ・ファイルだけ | このフォルダそのものには効かない（`CREATOR OWNER` によくある形） |
| サブフォルダだけ | |
| ファイルだけ | |

「このコンテナー内のオブジェクトやコンテナーにのみ…適用する」にチェックを付けた設定は、後ろに「（すぐ下だけ）」と書き添えます。ファイルの適用先は「このファイル」です。

### アカウントの種類

| 種類 | 例 |
| --- | --- |
| ユーザー | `CORP\yamada`、`FS01\localadmin` |
| グループ | `CORP\営業部`、`BUILTIN\Administrators`、`FS01\共有管理` |
| 組み込み | `Everyone`、`NT AUTHORITY\SYSTEM`、`CREATOR OWNER`、`NT AUTHORITY\Authenticated Users` など、Windows が決めているもの |
| コンピューター | `CORP\AP01$` |
| Windows のアプリ | `S-1-15-` で始まる、ストアのアプリなどに付く権限と、そこから作られる `S-1-5-32-<長い数>` のグループ。名前がないのが普通です |
| 名前が見つからない | 削除されたアカウントや、信頼関係のなくなったドメインのアカウント。アカウントの列には SID を出します |
| 名前を調べられない | ドメインコントローラーにつながらないなどで、問い合わせに失敗したもの。削除されたとは限らないので、「名前が見つからない」とは分け、確かめたほうがよいところには数えません。画面に「※ アカウントの名前を調べられなかったものがあります」と表示します |

共有フォルダ越しに調べるときは、サーバーのローカルのアカウント（`FS01\共有管理` など）の名前を、サーバーに問い合わせて調べます。

## 確かめたほうがよいところ

次のものに印を付けます。どれも「間違い」とは限りませんが、意図した設定かを確かめる価値があるものです。

| 種類 | 当てはまるもの | 確かめる理由 |
| --- | --- | --- |
| 継承を切っている | 継承を切っているフォルダ（ファイル） | 上のフォルダでアクセス権を変えても、ここには届かない。管理者が入れなくなっていることもある |
| 継承が親と合わない | 継承している設定が、親から継承するはずの設定と違うフォルダ（ファイル）。同じドライブの中で移動したものなど | 移動する前の場所のアクセス権が残っていて、今の親のアクセス権が効いていない |
| 個人を直接指定 | 種類が「ユーザー」のアカウントに付けたアクセス権 | 異動や退職のときに外し忘れやすい。グループにまとめるのが一般的 |
| 名前が見つからない | 種類が「名前が見つからない」のアカウントに付けたアクセス権 | 削除されたアカウントの設定が残っている |
| 広い範囲に書き込みを許可 | `Everyone`・`ANONYMOUS LOGON`・`Authenticated Users`・`Users`・`Guests`・`Domain Users`・`Domain Guests` に、書き込み・削除・アクセス権の変更・所有権の取得のどれかを許可している設定 | 誰でもファイルを置いたり消したりできる |
| 拒否 | 「拒否」の設定 | 拒否は許可より強く、グループの入れ子で思わぬ人まで締め出すことがある |
| 並び順が正しくない | アクセス権の並び順が、Windows の決まりと違うフォルダ | エクスプローラーで開くと警告が出て、正しく表示・変更できない |

- 共有のアクセス許可には印を付けません。「共有は `Everyone` にフル コントロールを付けて、NTFS のアクセス権で絞る」がよくある設定のためです
- 画面の件数は、アクセス権の行を、設定した場所で数えます。親から継承した設定は、調べ始めたフォルダ（`-Path` のフォルダ。`-Path` を省略したときと `\\fs01` のときは、各共有フォルダのフォルダ）と、継承が親と合わないフォルダの行でだけ数えます（同じ設定を、下のフォルダで何度も数えないため）。その中にある入れ子の共有フォルダでは数えません。CSV の「注意」の列には、継承した行にも印を付けます
- `D:\` の直下に共有フォルダを作ると、`D:\` の既定のアクセス権（`Users` にフォルダの作成を許可）を継承して、「広い範囲に書き込みを許可」に当てはまることがあります

## 調べる共有フォルダ

| `-Path` | 調べるもの |
| --- | --- |
| 指定しない | この PC の共有フォルダすべて |
| `\\fs01`（サーバー名だけ） | そのサーバーの共有フォルダすべて |
| `\\fs01\営業\見積`（共有フォルダの中） | `営業` の共有のアクセス許可と、`見積` から下の NTFS のアクセス権 |
| `D:\share`（この PC のフォルダ） | そのフォルダを含む共有と、その中にある共有の、共有のアクセス許可。NTFS のアクセス権は `D:\share` から下 |
| `Z:\`（ネットワークドライブ） | 割り当て先の共有フォルダとして扱います |

- 管理用の共有（`C$`・`ADMIN$`・`IPC$` など、Windows が自動で作るもの）と、プリンターの共有は、「すべて」に含めません。自分で作った名前の最後が `$` の共有（`総務$` など）は含めます
- 共有フォルダのフォルダが重なっているとき（`D:\share` と `D:\share\営業` の両方が共有になっているなど）は、外側のフォルダを 1 回だけ調べます。共有のアクセス許可は、両方とも表示します。外側の途中のフォルダを読めずに、内側のフォルダまで届かなかったときは、内側のフォルダを別に調べます。`-Path` に重なったフォルダを書いたときも同じです
  - ほかのサーバーの共有は、サーバーの上のフォルダの場所で重なりを判定します。サーバーの管理者でないと場所を読めないことがあり、そのときは重なりを判定できないため、両方を調べます
- 同じフォルダを 2 つの名前で共有しているときは、共有名を「data、data2」のように並べて書きます
- この PC に共有フォルダがないときに `-Path` を省略すると、止まって `-Path` を指定するよう案内します。`\\fs01` に共有フォルダがないときも止まります
- `-Path` を省略したときと `\\fs01` のときは、開けない共有フォルダがあっても止まらず、`skipped.csv` に残して、ほかの共有フォルダを調べます
- 共有のアクセス許可は、サーバーの管理者でないと読めないことがあります。読めないときは、理由を表示して、NTFS のアクセス権だけを調べます
- アクセス許可の設定が保存されていない共有（`C$` などの管理用の共有）は、Windows が既定の設定を使います。この PC の共有は、その既定の設定を読んで表示します。ほかのサーバーの共有は、「設定なし（Windows の既定のアクセス許可が使われます）」と表示します

## グループのメンバー

`-ExpandGroup` を指定すると、アクセス権（共有のアクセス許可と NTFS のアクセス権）に出てくるグループのメンバーを調べて、`groups.csv` に出します。

- 入れ子のグループもたどります。「経由」の列に、たどったグループを書きます。同じグループを 2 回たどることはありません（グループが互いに入っているときも止まります）
- ローカルのグループ（`BUILTIN\Administrators`、`FS01\共有管理` など）はその PC（共有フォルダ越しのときはサーバー）に、ドメインのグループはドメインコントローラーに問い合わせます。ドメインに参加していない PC から実行したときと、ローカルのアカウント（`FS01\Administrator` など）で実行したときは、ドメインのグループのメンバーは調べられません（「調べられなかったグループ」として理由を表示します）。ドメインのアカウントで実行してください
- 次のグループは、メンバーを調べません（`groups.csv` に 1 行だけ出して、備考に理由を書きます）
  - 組み込みのもの（`Everyone`、`Authenticated Users` など。グループではなく、条件で決まるため）
  - 広い範囲のグループ（`Users`・`Guests`・`Domain Users`・`Domain Guests`。ほぼ全員が入っているため）
- 調べられなかったグループ（ドメインコントローラーにつながらないなど）は、備考に理由を書き、画面にも表示します
- メンバーのいないグループは、1 行だけ出して、備考に「メンバーはいません」と書きます
- この一覧は、アクセス権の行とメンバーを並べたものです。ある人が実際にフォルダを開けるか（拒否、共有と NTFS の組み合わせ、ローカルのグループにドメインのグループが入っていることなど）は判定しません。1 人について確かめるときは、エクスプローラーの「セキュリティ」→「詳細設定」→「有効なアクセス」を使ってください

## そのほかのルール

- 隠しフォルダの中も調べます
- ジャンクションやシンボリックリンクはたどらず、`skipped.csv` に「リンク」として残します
- 中の一覧を読めないフォルダは、中を飛ばして件数を表示し、`skipped.csv` に残します。そのフォルダのアクセス権を読めるときは、アクセス権は一覧に出します
- アクセス権を読めないフォルダは、`skipped.csv` に「権限なし」として残します
- ごみ箱（`$RECYCLE.BIN`）と `System Volume Information` の中は調べず、`skipped.csv` に「除外指定」として残します
- 260 文字を超える長いパスや、名前に `[` `]` を含むフォルダ・ファイルも扱えます
- アカウントの名前は、SID ごとに 1 回だけ問い合わせます。ドメインコントローラーにつながらないときは、名前を調べるのに時間がかかることがあります
- 継承の印が付いていない古い形のアクセス権（自動継承の印のないフォルダの下に作ったフォルダ。Windows Server の `C:\` や、フォーマットしたままのドライブの下など）も、エクスプローラーと同じく、親のアクセス権と見比べて「親から継承」かどうかを判定します
  - ただし、古い形のアクセス権では、`CREATOR OWNER` から作られた所有者の設定（管理者が作ったフォルダの「Administrators フル コントロール このフォルダだけ」など）を、Windows は継承した設定として扱わず、エクスプローラーでも「継承元: なし」と表示します。だれかが足した設定ではないため、このツールは、そのフォルダで設定したものがそれだけのときは、親から継承した設定として扱います
- 監査の設定（SACL）は読みません
- 途中で中断（Ctrl+C）した場合は、結果を保存しません

| 終了コード | 意味 |
| --- | --- |
| 0 | 調べられた（読めなかったフォルダや共有があっても 0 です。件数は画面に表示します） |
| 1 | 引数の誤りなどで止まった |

## 止まるとき

次の場合は、調べ始める前にエラーを表示して止まります（終了コード 1）。

| 場合 | 表示の例 |
| --- | --- |
| `-Path` を省略したが、この PC に共有フォルダがない | 「この PC には共有フォルダがありません。調べるフォルダを -Path で指定してください」 |
| フォルダが見つからない・開けない | 「フォルダが見つかりません: D:\share」「フォルダを開けません: \\fs01\営業（アクセスが拒否されました。）」。管理者として開いた PowerShell でネットワークドライブを指定したときは、`\\サーバー名\共有名` の形で指定するよう案内します |
| サーバーの共有フォルダの一覧を読めない（`-Path \\fs01`） | 「サーバーの共有フォルダの一覧を読めません: \\fs01（ネットワーク パスが見つかりません。）」 |
| サーバーに共有フォルダがない（`-Path \\fs01`） | 「\\fs01 には共有フォルダがありません（C$ や ADMIN$ などの管理用の共有は含めません。…）」 |
| `-Path` にファイルを指定した | 「フォルダを指定してください（ファイルは指定できません）: D:\share\a.xlsx」 |
| アクセス権のないファイルシステム（FAT32・exFAT） | 「このドライブ（FAT32）には、アクセス権がありません: E:\」 |
| `-Depth` が範囲外 | 「-Depth は 1～100 の数値で指定してください: 0」 |
| 値に `"` が残っている（コマンドプロンプトで `"D:\share\" -All` のように、最後が `\"` の値の後ろに引数が続いた） | 「-Path の値に引用符（"）が残っています: …」と、正しい書き方 |
| どのパラメーターにも当たらない引数がある（パラメーターの名前の書き間違いなど） | 「どのパラメーターにも当たらない引数があります: …」 |
| 制約付き言語モード（AppLocker や WDAC の環境） | 「制約付き言語モードでは使えません（AppLocker や WDAC でスクリプトの実行が制限されている環境です）」 |
| Windows の API を呼ぶ準備ができない（`Add-Type` を使えない） | 「Windows の API を呼ぶ準備ができません（Add-Type を使えません）」 |

## 共有フォルダを調べるとき

- `-Path \\サーバー名\共有名` の形で指定してください。管理者として開いた PowerShell からは、通常の権限で割り当てたネットワークドライブ（`Z:` など）が見えないことがあります
- 実行したユーザーの権限で読みます。共有のアクセス許可は、サーバーの管理者でないと読めないことがあります
- 共有フォルダのフォルダ（`\\fs01\営業` そのもの）は、共有越しには親のフォルダをたどれません。継承の印のない古い形のアクセス権（Windows Server の `C:\` や、フォーマットしたままのドライブの下に作り、アクセス権を変えていないフォルダなど）では、Windows が親から継承した設定も「このフォルダで設定した」として返します。そのときは、サーバーの管理共有（`\\fs01\D$\share\営業`）越しに読み直して、継承した設定を見分けます。サーバーの管理者でないなどで読み直せないときは、「このフォルダ」の設定として出し（状態は「追加している」になります）、画面に「※ 共有フォルダのフォルダで、親から継承した設定を見分けられなかったものがあります」と表示します
- ネットワーク越しにフォルダを 1 つずつ読むため、ローカルのフォルダより時間がかかります。ファイルサーバーにログオンできる場合は、サーバーの上で `-Path` を省略して（または `D:\share` のようなローカルのパスで）実行するほうが速く終わります
- DFS の名前空間のパス（`\\corp.local\dfs\営業` など）を指定すると、共有のアクセス許可は、フォルダの実体がある共有のものになりません。実体のサーバーの共有（`\\fs01\営業`）を指定してください

## 使うときの注意

- **この一覧は、フォルダに付けたアクセス権を並べたものです。** ある人が実際に開けるかは、グループのメンバー、拒否、共有と NTFS の組み合わせで決まります。ネットワーク越しのアクセスでは、共有のアクセス許可と NTFS のアクセス権の、厳しいほうが効きます
- 管理者でも、アクセスを拒否されているフォルダ（本人だけに権限を付けたホームフォルダなど）は、中を読めません。`skipped.csv` に残します
- 結果には、ユーザー名とグループ名が入ります。社外に出すときは、中身を確かめてください

## 動作環境

[リポジトリの README の「システム要件」](../../README.md#システム要件)を参照してください。管理者権限は不要です。ほかのユーザーのフォルダや、サーバーの共有のアクセス許可を調べるときは、管理者として実行してください。

アクセス権と共有のアクセス許可を読むこと、アカウントの種類を調べることに Windows の API を使います。`Add-Type` で呼ぶため、実行のたびに C# のコンパイルが 1 秒ほど走ります。`Add-Type` を使えない環境では使えません。
