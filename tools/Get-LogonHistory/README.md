# Get-LogonHistory（ログオンの履歴）

このサーバーに、誰が・いつ・どこからログオンしたか（リモートデスクトップかどうか）、いつログオフしたか、ログオンに失敗していないかを、Security ログから一覧にします。結果は画面に表示し、CSV にも保存します。

「障害が起きた時間帯に、誰かサーバーに入っていなかったか」「作業の記録と、実際にログオンしていた時間が合っているか」「パスワードを総当たりで試されていないか」を確かめるときのための道具です。リモートデスクトップの切断と再接続も分かります。イベント ビューアーで 1 件ずつ開いて、ログオン ID をたどる手間を省きます。イベントログを変更・削除することはありません。

## 使い方

```powershell
# 直近 7 日のログオン（対話・リモートデスクトップ・ロック解除）と、ログオンの失敗を一覧にする
powershell -ExecutionPolicy Bypass -File .\Get-LogonHistory.ps1
```

**管理者として実行してください。** Security ログは、管理者でないと読めません。実行ポリシーなど、起動方法の詳しい説明は[リポジトリの README](../../README.md#使い方) を参照してください。

### 例

```powershell
# 障害の時間帯を指定する
powershell -ExecutionPolicy Bypass -File .\Get-LogonHistory.ps1 -Since "2026-11-10 22:00" -Until "2026-11-11 02:00"

# 特定のユーザーだけを見る（* が使えます）
powershell -ExecutionPolicy Bypass -File .\Get-LogonHistory.ps1 -Since 30d -User "yamada,*admin*"

# リモートデスクトップだけを見る
powershell -ExecutionPolicy Bypass -File .\Get-LogonHistory.ps1 -LogonType RemoteDesktop

# ファイル共有へのアクセス（ネットワークのログオン）も含めて、すべての種類を見る
powershell -ExecutionPolicy Bypass -File .\Get-LogonHistory.ps1 -Since 1d -LogonType All

# ほかのサーバーから集めた .evtx ファイルを読む
powershell -ExecutionPolicy Bypass -File .\Get-LogonHistory.ps1 -Path D:\collected\ap01 -Since 30d
```

## パラメーター

| パラメーター | 内容 | 既定値 |
| --- | --- | --- |
| `-Since` | この日時以降の記録を取り出します。`"2026-11-10 09:00"` のような日時か、`2h`（2 時間前）・`30m`（30 分前）・`3d`（3 日前）のような今からの時間で書きます。書き方は [Search-Log の -Since](../Search-Log/README.md#パラメーター) と同じです | `7d`（直近 7 日） |
| `-Until` | この日時までの記録を取り出します。書き方は `-Since` と同じです | 指定なし（今まで） |
| `-User` | 取り出すユーザー。`"yamada,CORP\suzuki"` のようにカンマで区切って書けます。`*` は任意の文字列です（`"*admin*"`）。ドメインを付けないと、どのドメインのユーザーにも当たります。大文字と小文字は区別しません | 指定なし（すべてのユーザー） |
| `-LogonType` | 取り出すログオンの種類。`Interactive`（対話）、`RemoteDesktop`（リモートデスクトップ）、`Unlock`（ロック解除）、`Network`（ネットワーク）、`Batch`（バッチ）、`Service`（サービス）、`NewCredentials`（別の資格情報）を、カンマで区切って書きます。日本語（`"対話,リモートデスクトップ"`）でも書けます。`All` ですべての種類です | `Interactive,RemoteDesktop,Unlock` |
| `-Path` | 読む .evtx ファイル、または .evtx ファイルのあるフォルダ（サブフォルダも探します）。カンマで区切って複数書けます。Security ログと、リモートデスクトップのセッションのログ（`Microsoft-Windows-TerminalServices-LocalSessionManager%4Operational.evtx`）を読みます。指定すると、この PC のイベントログは読みません | 指定なし（この PC のイベントログを読む） |
| `-OutputFolder` | 結果の保存先 | スクリプトと同じフォルダ |
| `-NoSave` | 結果を保存せず、画面表示だけにします。`-OutputFolder` と一緒には使えません | なし |

- ログオンの失敗は、`-LogonType` に関係なく、すべての種類を取り出します。リモートデスクトップのパスワードの総当たりも、Windows はネットワークの種類（ネットワーク レベル認証で失敗したもの）として記録するためです。`-User` と期間では絞り込みます
- 設定ファイル（`-ConfigFile`）はありません。決まった条件で実行するときは、コマンドをバッチファイルに書いておいてください

## 画面の表示例

```
ログオンの履歴 (Get-LogonHistory 1.0.0)
対象: SERVER01（管理者: はい）   Security ログ: 2026-10-28 09:12 から残っています
期間: 2026-11-05 15:00 ～ 2026-11-12 15:00（7 日）   種類: 対話, リモートデスクトップ, ロック解除

■ ユーザーごと
 ユーザー                ログオン  最後のログオン       失敗  最後の失敗
 CORP\yamada                   12  2026-11-12 09:03:11     0
 SERVER01\Administrator         3  2026-11-10 22:15:40     2  2026-11-10 22:14:58

■ ログオン（新しい順・20 件まで）
 ログオン             ログオフ             時間     ユーザー                種類                  接続元         管理者
 2026-11-12 09:03:11  （切断中）                    CORP\yamada             リモートデスクトップ  192.168.10.21  はい
 2026-11-11 18:40:05  2026-11-11 19:02:44  0:22:39  CORP\yamada             リモートデスクトップ  192.168.10.21  はい
 2026-11-10 22:15:40  2026-11-10 22:30:12  0:14:32  SERVER01\Administrator  対話                                 はい
 ...

■ ログオンの失敗（ユーザーと接続元ごと）
 件数  ユーザー                接続元         最後                 理由
    2  SERVER01\Administrator  192.168.10.99  2026-11-10 22:14:58  パスワードが違う

ログオン 15 件（ロック解除 9 回・切断 4 回・再接続 3 回）  失敗 2 件  所要 1.8秒
保存先: C:\tools\LogonHistory_SERVER01_20261112_150000
```

表示の決まりは次のとおりです。

- 「ユーザーごと」は、ログオンの多い順に表示します
- 「ログオン」は、ログオンした時刻の新しい順に 20 件まで表示します。すべてのログオンは `sessions.csv` に保存します。ロック解除・切断・再接続は、そのログオンの行に数えます（1 回ずつの時刻は `events.csv` にあります）
- 「ログオフ」の列は、ログオフの記録がないときに、次のように表示します（[ログオンとログオフの組み合わせ](#ログオンとログオフの組み合わせ)を参照）
  - `（ログオン中）`：今もそのログオンが続いている
  - `（切断中）`：リモートデスクトップを切断したまま、ログオフしていない
  - `（再起動）`：ログオフの記録がないまま、OS が起動し直している
  - `（記録なし）`：上のどれでもない（ログオフの記録が消えた、OS が止まったなど）
- 「時間」は、ログオンからログオフまでの長さです（`0:22:39`、1 日を超えると `1日 2:03:00`）
- 「管理者」は、管理者の権限（UAC で昇格できる権限）を持ったログオンかどうかです
- 「ログオンの失敗」は、ユーザーと接続元が同じものを 1 行にまとめ、件数の多い順に 20 件まで表示します。すべての失敗は `events.csv` に保存します
- 表示しきれなかった分は「（ほか 12 件は sessions.csv を参照してください）」のように表示します。`-NoSave` のときと、保存先のフォルダを作れなかったときは、すべて表示します
- ユーザーと接続元は、長いときは半角 24 文字分で切り、最後を `…` にします（CSV にはすべて書きます）
- 条件によって、次の行も表示します
  - `-Path` を指定したとき：「対象」の行が「対象: D:\collected\ap01\Security.evtx ほか 1 ファイル」
  - `-User` を指定したとき：「条件: ユーザー yamada, *admin*」
  - 期間の始めより前の記録が、もう Security ログに残っていないとき：「※ 2026-10-28 09:12 より前の記録は、Security ログに残っていません（上書きされています）」
  - リモートデスクトップのセッションのログが、期間の途中からしか残っていないとき：「※ 2026-11-08 10:00 より前の切断・再接続は分かりません（セッションのログに残っていません）」
  - Security ログが消去された記録があるとき：「※ 2026-11-08 10:00 に Security ログが消去されています（CORP\yamada）」
  - 監査ポリシーで、ログオンの成功か失敗を記録しない設定になっているとき：「※ ログオンの失敗を記録しない設定です（監査ポリシー）。失敗は表示されません」
  - 読めなかったログやファイルがあったとき：「スキップ 1 件（権限なし）」
- 記録が 1 件もないときは「該当する記録はありません」と表示します

## 保存されるファイル

実行するたびに、保存先に `LogonHistory_<ホスト名>_<日時>` というフォルダを作り、次のファイルを保存します。

| ファイル | 内容 |
| --- | --- |
| `summary.txt` | 画面に表示した内容。一覧は 20 件を超えても省略しません |
| `sessions.csv` | ログオンごとの一覧（ログオンの新しい順） |
| `events.csv` | ログオン・ログオフ・ロック解除・切断・再接続・失敗・OS の起動・ログの消去の、すべての記録（新しい順） |
| `users.csv` | ユーザーごとの集計（ログオンの多い順） |
| `skipped.csv` | 読めなかったログやファイルと、その理由 |

CSV とテキストは BOM 付き UTF-8 で保存します。保存先に書き込めないときは、集め始める前にエラーで止まります（`-NoSave` を付ければ、画面に表示だけできます）。

### CSV の列

| ファイル | 列 |
| --- | --- |
| `sessions.csv` | ログオン、ログオフ、時間、ユーザー、種類、接続元 IP アドレス、接続元の名前、管理者権限、状態、ロック解除の回数、切断の回数、再接続の回数、最後の切断、認証、ログオン ID、コンピューター |
| `events.csv` | 日時、操作、ユーザー、種類、接続元 IP アドレス、接続元の名前、詳細、ログオン ID、セッション ID、イベント ID、コンピューター |
| `users.csv` | ユーザー、ログオン回数、最初のログオン、最後のログオン、合計の時間、失敗回数、最後の失敗 |
| `skipped.csv` | 理由、対象、詳細 |

- 日時は `2026/11/12 09:03:11` の形で、実行した PC の時刻で書きます
- ユーザーは `ドメイン\ユーザー名` の形です（ローカルのユーザーは `コンピューター名\ユーザー名`）
- `sessions.csv` の状態は、「ログオフ」「ログオン中」「切断中」「再起動」「記録なし」のいずれかです。ログオフの記録がないときは、ログオフと時間を空欄にします
- `events.csv` の操作は、「ログオン」「ログオフ」「ロック解除」「切断」「再接続」「ログオンの失敗」「OS の起動」「ログの消去」のいずれかです。詳細には、失敗の理由（「パスワードが違う」など）と状態コード、管理者権限などを書きます
- 種類は、「対話」「対話（runas）」「対話（キャッシュ）」「リモートデスクトップ」「ロック解除」「ネットワーク」「バッチ」「サービス」「別の資格情報」などです
- 認証は、「Kerberos」「NTLM」などです
- 接続元の名前は、ログオンの記録に入っている端末の名前です（ないときは空欄です）
- 名前や値のうち、Excel で数式・数値・日付に変わる形のもの（`=` `+` `-` `@` で始まるものなど）は、`="..."` の形で書きます
- `skipped.csv` の理由は、「権限なし」「ログがない」「ファイルを読めない」「対象外のログ」（`-Path` で指定した、Security でもセッションのログでもない .evtx）「リンク」（`-Path` のフォルダの下のジャンクションなど。たどりません）「その他のエラー」のいずれかです

## 取り出しのルール

### 読む記録

| 記録 | ログ | イベント ID |
| --- | --- | --- |
| ログオン | Security | 4624 |
| ログオンの失敗 | Security | 4625 |
| ログオフ | Security | 4634、4647 |
| OS の起動 | Security | 4608 |
| ログの消去 | Security | 1102 |
| 切断・再接続 | リモートデスクトップのセッションのログ（`Microsoft-Windows-TerminalServices-LocalSessionManager/Operational`） | 21、23、24、25 |

ログオンの種類と、Windows の記録のログオンの種類（LogonType）の対応は次のとおりです。

| `-LogonType` | 種類（画面・CSV） | LogonType |
| --- | --- | --- |
| `Interactive`（対話） | 対話、対話（runas）、対話（キャッシュ） | 2、11 |
| `RemoteDesktop`（リモートデスクトップ） | リモートデスクトップ、リモートデスクトップ（キャッシュ） | 10、12 |
| `Unlock`（ロック解除） | ロック解除、ロック解除（キャッシュ） | 7、13 |
| `Network`（ネットワーク） | ネットワーク、ネットワーク（平文） | 3、8 |
| `Batch`（バッチ） | バッチ（タスクスケジューラなど） | 4 |
| `Service`（サービス） | サービス | 5 |
| `NewCredentials`（別の資格情報） | 別の資格情報（`runas /netonly` など） | 9 |

- 「対話（runas）」は、`runas` や「別のユーザーとして実行」でのログオンです。「キャッシュ」は、ドメインコントローラーにつながらないときに、保存された資格情報でログオンしたものです
- 期間・イベント ID・ログオンの種類の絞り込みは、イベントログの側で行うため、イベントが多いログでも速く取り出せます。`-User` は、取り出した後に絞り込みます
- OS の内部で使うアカウントのログオンは除きます。SYSTEM、LOCAL SERVICE、NETWORK SERVICE、ANONYMOUS LOGON、画面の表示に使う `DWM-1` や `UMFD-0` のようなアカウント、コンピューターのアカウント（名前が `$` で終わるもの）です。ログオンの失敗は除きません
- ログオンの失敗の理由は、記録の状態コードから「パスワードが違う」「ユーザー名がない」「アカウントが無効」「アカウントがロックされている」「パスワードの期限切れ」「ログオンできる時間外」「このログオンの種類は許可されていない」などに直します。直せない状態コードは「その他（0xC000…）」と書きます

### ログオンとログオフの組み合わせ

- ログオンとログオフは、ログオン ID で組にします。ログオフの記録が 2 つあるとき（4647 と 4634）は、早いほうをログオフの時刻にします
- 管理者が UAC の有効な環境でログオンすると、管理者の権限のあるログオンとないログオンが、同時に 2 つ記録されます。この 2 つは 1 行にまとめ、管理者権限を「はい」にします
- ログオフの記録がないときは、次の順に判定します
  1. この PC で実行していて、そのログオンが今も続いている：「ログオン中」
  2. リモートデスクトップのセッションのログで、最後の記録が切断：「切断中」
  3. ログオンの後に OS の起動の記録がある：「再起動」
  4. どれでもない：「記録なし」
- ロック解除は、同じユーザーの、そのときに続いているログオンの行に数えます（`-LogonType` に `Unlock` を含むときだけ）
- リモートデスクトップの切断・再接続は、セッションのログのログオンの記録と、Security ログのログオンを、ユーザー・時刻・接続元で組にして、そのログオンの行に数えます。再接続のときに Security ログに記録されるログオンは、新しいログオンとしては数えず、`events.csv` に「再接続」として書きます
- セッションのログは大きさが小さく（既定で 1 MB）、古い記録から消えていきます。セッションのログに残っていない期間の切断・再接続は分かりません（画面に注意を表示します）

### 読めないとき

- この PC の Security ログを読めないとき（管理者でないとき）は、エラーで止まります（終了コード 1。[止まるとき](#止まるとき)を参照）
- セッションのログを読めないときは、切断・再接続を数えずに続け、`skipped.csv` に残します
- `-Path` のファイルのうち、壊れているものや読めないものは飛ばして、`skipped.csv` に残します（途中で壊れているときは、読めたところまでを結果に含めます）。すべて読めなかったときは、エラーで止まります

## 終了コード

| 終了コード | 意味 |
| --- | --- |
| 0 | 該当する記録（ログオンかログオンの失敗）があった |
| 2 | 該当する記録がなかった |
| 1 | 引数の誤りや、Security ログを読めなかったなどで、止まった |

## 止まるとき

次の場合は、エラーを表示して止まります（終了コード 1）。

| 場合 | 表示の例 |
| --- | --- |
| 管理者でなく、Security ログを読めない | 「Security ログを読む権限がありません。管理者として実行してください」と、「ほかの PC から集めた .evtx ファイルは、-Path で読めます（管理者でなくても読めます）」 |
| `-LogonType` に知らない種類を書いた | 「-LogonType に使えない種類があります: Remote」と、使える種類の一覧 |
| `-Since` や `-Until` の書き方が違う、`-Since` が `-Until` より後 | 「-Since の日時を読めません: 2026-13-01」 |
| `-NoSave` と `-OutputFolder` を一緒に指定した | 「-NoSave のときは、-OutputFolder は指定できません」 |
| 値に `"` が残っている（コマンドプロンプトで `"C:\data\"` のように最後を `\"` にした） | 「-OutputFolder の値に引用符（"）が残っています: …」と、正しい書き方 |
| 保存先に書き込めない | 「保存先に書き込めません: \\fileserver\logon（理由）」と、「-NoSave を付けると、画面に表示だけします」 |
| `-Path` のファイルをすべて読めなかった | 「読める .evtx ファイルがありません」 |
| 制約付き言語モード（AppLocker や WDAC の環境） | 「制約付き言語モードでは使えません（AppLocker や WDAC でスクリプトの実行が制限されている環境です）」 |

## 使うときの注意

- **管理者として実行してください。** Security ログは、管理者でないと読めません。ほかの PC から集めた .evtx ファイルは、管理者でなくても `-Path` で読めます（ファイルを読む権限があれば読めます）
- **実行したサーバーへのログオンだけを調べます。** ドメイン全体のログオンは扱いません。ドメインコントローラーで実行しても、そのドメインコントローラー自体へのログオン（対話・リモートデスクトップなど）だけです
- **監査ポリシーで、ログオンの記録が無効になっていると、記録されません。** 管理者として実行したときは、設定を確かめて、無効なら画面に注意を表示します
- **イベントログの保存できる大きさを超えると、古い記録から消えていきます。** 画面の「Security ログ: … から残っています」で、どこまでさかのぼれるかを確かめてください。ログオンの多いサーバー（ファイルサーバーやドメインコントローラー）では、数日分しか残っていないことがあります
- リモートデスクトップの切断・再接続は、セッションのログ（既定で 1 MB）に残っている期間だけ分かります
- ロック解除は、Windows が Security ログに記録するロック解除のログオンで数えます。画面のロックの時刻は分かりません（既定の監査ポリシーでは記録されないためです）
- 期間は、実行した PC の時刻で解釈します。ほかのサーバーの .evtx を読むときに、そのサーバーと時間帯の設定が違うと、表示する日時もずれます
- 結果には、ユーザー名と接続元の IP アドレスが入ります。社外に出すときは中身を確かめてください
